## What works

- **The page is a clear color and nothing else.** The entire shipped stylesheet is ~14 declarations and **two** custom properties (`--bgColor: #A0A5B1`, `--default-font: sans-serif`); the whole document body is `<div id="app"><div id="webgl"></div></div>`. The one styling decision that matters is that the HTML background is set to *the renderer's clear color*, so the handoff from "browser painted the document" to "WebGL painted its first frame" is invisible — no white flash, no letterbox, no skeleton. **Transferable rule:** whenever a canvas owns the viewport, hoist its clear color into a CSS custom property and paint `html`/`body` with it. One variable buys you a free, correct loading state. See `clear-color-canvas-shell`.

- **The preloader IS the narrative, not a spinner.** Across the frame sequence the scene doesn't fade in — it gets *built*. A luminous wireframe dome with numeric part annotations (s00) grows a tessellating scaffold outward across the ground plane (s02, with a bloom flaring at the apex like a weld), then materials resolve onto the geometry, terrain textures precipitate in, the camera dollies back to reveal a landscape (s05→s08), and the scaffold decays to a faint atmospheric lattice (s09–s10). The asset wait was reframed as a *construction sequence*. **Transferable rule:** if an experience must stall for payload, spend the stall telling the story of the thing arriving. A blueprint-to-render ramp costs almost nothing (opacity + material swap + one camera move) and converts dead time into the most memorable beat on the page. See `blueprint-assembly-preloader`.

- **Monochrome forces the subject to carry all contrast.** Every pixel lives on one cool blue-grey axis (roughly `#A0A5B1` field → `#E8EBEF` snow → `#FFFFFF` rim). With hue held constant, the only ordering device left is **luminance**, so the eye goes straight to the brightest thing — the rim-lit mortar seams of the ice blocks and the glow at the dome's crown. Nothing competes. **Transferable rule:** when one object must dominate a composition, remove hue as a variable rather than adding contrast to the object. A single-hue field makes rim light legible as hierarchy; a colorful one turns it into noise.

- **Two font *families*, one weight, zero scale.** The site self-hosts `IBMPlexMono-Regular` and `IBMPlexMono-Medium` as **separate `@font-face` families, both declared `font-weight: 400`**. Emphasis is a family swap, never a weight change — and because the type is drawn into the WebGL layer rather than laid out by CSS, there is no responsive type scale at all. The mono grid is what makes the HUD read as instrumentation instead of marketing copy. **Transferable rule (the good half):** a monospace face at a single weight, differentiated only by optical density, gives interfaces a technical register that no amount of "modern sans + bold" achieves. **The bad half is below** — do not put the text in the canvas.

- **Refusing the scroll gesture is a design decision, and it is stated in CSS.** `html, html body { overflow: hidden; touch-action: none; }` on a full-height document is the site declaring that the wheel and the finger belong to the scene, not the document. There is no scroll position to observe; the eleven captured "scroll frames" are eleven *time* samples of a page that cannot scroll. **Transferable rule:** if you intend to consume pointer/wheel input for a simulation, disable document scroll and touch panning explicitly at the root — a canvas that fights the page's native scroll is the single most common cause of "this site feels broken on mobile." The corollary: only do this when the canvas is the *entire* product, because you have just deleted the reader's most practiced gesture.

- **The wireframe never fully leaves.** The scaffold lattice does not animate to zero; it settles at a very low opacity and stays, drawn over the finished render for the life of the session (visible in s08–s10 and still faintly present in the resting mobile frame). It costs one always-on line pass and it keeps the scene in an "engineered artifact" register rather than a "photograph" one. **Transferable rule:** a construction artifact retained at 5–10% opacity is a cheap way to say *this was made, deliberately* — the same move as leaving a grid overlay in an editorial layout.

## Design-system read

- **Type:** One face, `IBM Plex Mono`, shipped as two *families* (`-Regular`, `-Medium`) that both declare `font-weight: 400` — so the CSS weight axis is never used; contrast comes from family substitution. `font-display: swap`, self-hosted woff2 + woff from the site's own origin (no font CDN). There is **no type scale**: the only computed `font-size` anywhere in the DOM is `16px` across all four nodes, because every glyph the user sees is rasterized into the WebGL layer. `--default-font: sans-serif` is declared and never consumed — a leftover. What the screenshots show is a single mono size for HUD labels and one oversized, pixel-crushed wordmark; the "scale" is a texture-atlas decision, not a CSS one.
- **Color:** A one-hue system. `bg` = `#A0A5B1` (the declared `--bgColor`, and the scene's clear color — they are the same value by design). Everything else is a luminance step on that same cool blue-grey: `sky #C3C7CE` → `snow #E8EBEF` → `rim/highlight #FFFFFF`, with `shadow #5E6572` under the ice blocks. The only *hard* hexes in the stylesheet besides the background are the custom scrollbar colors on the debug panel — `track #4C4F53`, `thumb #777C81` — which double as the HUD's dark plate value in the render. There is **no accent**. No gradient is declared in CSS; all gradation is lighting.
- **Spacing rhythm:** None exists in CSS. Every box is `0` margin, `0` padding, `100%`/`100%`. Spatial rhythm in the composition — the HUD plates hugging the four corners with a consistent viewport-relative inset — is laid out by the renderer, so it is a scene-graph decision, not a token scale. Honest read: **this site has no spacing system to steal.**
- **Layout system:** `#app` is `position: absolute; inset: 0` inside a `height: 100%` html/body with `overflow: hidden`; `#webgl` is `position: absolute; 100% × 100%` inside it. That is the entire layout. Zero grid, zero flex, zero media queries, zero declared breakpoints. The `viewport-fit=cover` + `minimal-ui` meta is the mobile-specific art direction — the scene is allowed to run under the notch and the browser chrome. Responsiveness is handled by the camera (mobile reframes to a tight portrait crop of the same igloo, per `mobile.png`), not by reflow.
- **Layering / page architecture:** Flat, and deliberately so. `architecture.layers_summary` reports **0 fixed, 0 sticky, no static backdrop, no blend overlay**; `blend_glass` and `z_stack` are empty. There is exactly one absolutely-positioned box in the tree. **All depth on this page is simulated inside the canvas** — the rim lighting, the atmospheric haze on the far ridge, the parallax between the wireframe lattice and the terrain. Nothing is achieved with CSS z-index, blend modes, or backdrop filters, because there is nothing to layer. The z-axis story is: *there is no z-axis in the document; the document is a window.*
- **Motion / easing intent:** Unmeasurable from CSS, and that is itself the finding: **0 `@keyframes`, 0 CSS animation rules, 0 transition rules, 0 `prefers-reduced-motion` blocks, 0 scroll listeners, 0 IntersectionObservers.** The probe counts **197 `requestAnimationFrame` callbacks and exactly 1 `mousemove` listener**. Every duration and easing on this site lives in JavaScript inside a render loop, so no `--duration-*` / `--ease-*` values can be honestly extracted. The intent the frames communicate is *machinery*: nothing eases in, things are assembled, and once assembled the loop never stops.
- **Density:** Effectively zero in the DOM (4 nodes, 0 headings, 0 images, 0 buttons, 0 landmarks) and low in the render — one object, one horizon, four small text plates. The composition can afford a garish 100%-white HUD plate precisely because 95% of the frame is a narrow mid-grey band.
- **Hierarchy:** **Luminance, then position.** The brightest object (the lit dome) is the subject; the second-brightest (pure-white HUD plates) are the labels; everything else recedes into the grey. Position is the tiebreaker — the four corners are chrome, the center is content. Scale, weight, and color are not used as ordering devices at all.
- **Restraint:** No hue. No gradient. No shadow. No radius. No second typeface. No weight axis. No scroll. No hero headline in the DOM. No cookie banner, no nav bar, no footer. The restraint is total and it is also, in a11y terms, the site's undoing — see below.

## Interaction & motion

**Evidence and its limits.** This is the purest canvas-first site in the corpus: **197 rAF callbacks, 1 `mousemove` listener, 0 IntersectionObservers, 0 scroll listeners, 0 `@keyframes`, 0 CSS animation/transition rules, 0 `prefers-reduced-motion` rules, 0 detected libraries** (the bundle is a single crossorigin ES module; `Three`/`GSAP` are not exposed as globals). The DOM contains nothing that *can* animate. Consequently the eleven captured frames are **time samples of the load sequence, not scroll depth** — the document has `overflow: hidden` on a 100%-height body and literally cannot scroll. Every technique below is read off the frame sequence and the probe counts; none can be attributed to a CSS rule, and none is directly copyable — what transfers is the *choreography*, re-implementable in any renderer or, for the preloader, in plain SVG.

- **Blueprint-to-render assembly** — *Trigger:* load (asset-progress driven, inside the rAF loop). *Mechanism:* the subject is drawn first as a self-luminous wireframe carrying numeric part annotations (s00); a scaffold lattice tessellates outward across the ground plane while a bloom flares at the dome's apex (s02); PBR materials then resolve onto the geometry and terrain textures precipitate in (s05→s08) as the camera dollies back from a tight isometric to a landscape framing (s09→s10). Three ramps — line-opacity, material-mix, camera position — sequenced, not concurrent. *Reads as:* the thing is being *built for you*, right now; the wait is the show. *Transfers to:* any experience with an unavoidable payload — 3D configurators, map viewers, data-heavy dashboards. The DOM/SVG reduction of this (stroke-dashoffset draw-on → cross-fade to the finished raster) is a drop-in for hero images and product shots. *Safety:* **spectacle-only** as shipped (unbounded GPU work, no reduced-motion gate); the SVG reduction is production-safe. → `blueprint-assembly-preloader`.

- **Persistent wireframe residue** — *Trigger:* load (terminal state of the ramp above). *Mechanism:* the scaffold's opacity ramp terminates near zero but not *at* zero; a faint white line pass survives over the finished render and continues to draw every frame. *Reads as:* the render is a schematic that happens to be photoreal — an engineered artifact, not a photograph. *Transfers to:* editorial and product surfaces that want to admit their own construction; the CSS analogue is a retained baseline/column grid at ~6% opacity. *Safety:* **production-safe** as a static overlay (one `background-image` or SVG layer, zero runtime cost); **spectacle-only** if you keep redrawing it in a loop the way this site does.

- **Pointer-driven camera parallax** — *Trigger:* pointer move (the single `mousemove` listener; there is nothing else it could plausibly drive). *Mechanism:* cursor position feeds the scene camera's rotation/offset, so the ridge line and the wireframe lattice shear against the igloo at different rates. *Reads as:* the window is a real aperture onto a place that extends past its edges. *Transfers to:* any single-subject hero — the same effect is achievable with two or three CSS layers translated by a few pixels each on `pointermove`. *Safety:* **spectacle-only** — fine-pointer only (a touch device gets no payoff and pays the listener cost), a known motion-sickness trigger, and this implementation offers no reduced-motion escape. Gate on `@media (pointer: fine) and (prefers-reduced-motion: no-preference)` and cap displacement to a few pixels.

- **Document gesture capture** — *Trigger:* wheel / touch. *Mechanism:* declared in CSS, not JS — `html, html body { overflow: hidden; touch-action: none; }` on a full-height document. Wheel and touch never reach a scroll container, so the render loop is free to consume them for camera work. *Reads as:* immersion; the browser stops behaving like a browser. *Transfers to:* full-viewport canvas apps, map UIs, games. *Safety:* **spectacle-only, and the highest-cost decision on the page.** It removes the reader's most practiced gesture, breaks browser find-in-page and keyboard scrolling, and leaves no fallback if WebGL fails or the module 404s — the user gets a permanently blank `#A0A5B1` rectangle. Never apply it to a page that also has to serve prose. → `clear-color-canvas-shell` shows the gated version.

- **Ambient render loop (no resting state)** — *Trigger:* load, continuous. *Mechanism:* 197 rAF callbacks; the loop never yields. *Reads as:* liveness. *Safety:* **spectacle-only** — sustained GPU/CPU draw and battery drain with no `IntersectionObserver` to pause it when backgrounded and no reduced-motion gate. At minimum: pause on `visibilitychange` and when the canvas leaves the viewport.

**Components.** There are none. `element_census` reports 0 `<button>`, 0 `<input>`, 0 `<form>`, 0 `<canvas>` *at probe time* (the canvas is injected by the module after first paint), 0 `<svg>`, 0 `<img>`, and 0 `header`/`nav`/`main`/`footer` landmarks. `craft.states.focus` and `.disabled` are empty because nothing focusable exists. The wordmark, the four HUD text plates, and any navigation the user sees in `mobile.png` are **rasterized into the WebGL layer** — they are pixels, not elements.

**Grid / container.** None. `layout.display` is `{grid: 0, flex: 0}`, `container_widths` is empty, `breakpoints` is empty, `gridCols` is empty. Composition is a camera, not a grid.

**Stack provenance.** Single crossorigin ES module (Vite-hashed asset names), self-hosted woff2. The stylesheet styles `.tp-dfwv` — **Tweakpane's debug-panel class** — including its scrollbar track and thumb. A live parameter GUI was left wired into the production bundle: strong evidence that every value in this scene was hand-tuned by eye rather than derived from a system, which is consistent with the total absence of a token scale.

**A11y (honest, and severe).** `reduced_motion: false` — **`prefers-reduced-motion` is not respected**, and the page is an unbounded render loop with pointer-driven camera motion, which is the exact combination that triggers vestibular symptoms. `focus_visible: false` with `interactive_count: 0` — there is **nothing to focus**, so keyboard users cannot reach any of the site's content or links. `img_count: 0` and `headings: {h1: 0 … h6: 0}` with zero landmarks — **a screen reader encounters an empty document**, and the site's entire message survives only in the `<meta name="description">` and the Open Graph card. There is no `<noscript>`, no static poster, no WebGL-failure path. This exemplar is filed as a lesson in *choreography and material discipline*; its DOM strategy is a defect to be corrected, not copied.

## Production-safety note

- **Clear-color page shell (`--bgColor` = renderer clear color)** — *production-safe, recommended.* One custom property, zero cost, eliminates the load flash. The only caveat is to actually keep a real DOM text layer above the canvas (this site does not) so the page has content when JS or WebGL fails. → `clear-color-canvas-shell`.
- **Blueprint-to-render assembly sequence** — *spectacle-only as shipped, production-safe in its SVG reduction.* The WebGL version costs a full asset payload and an ungated animation. The reduction — an inline SVG wireframe drawing itself via `stroke-dashoffset`, cross-fading to the finished raster — is compositor-cheap, gateable, and degrades to "the image is simply there" under reduced motion. → `blueprint-assembly-preloader`.
- **Persistent wireframe residue** — *production-safe as a static overlay* (an SVG or `background-image` at ~6% opacity); *spectacle-only* if redrawn per frame.
- **Pointer-driven camera parallax** — *spectacle-only.* Motion-sickness risk, no touch payoff, main-thread listener. Gate on fine pointer + no-preference; cap displacement; never move text with it.
- **Document gesture capture (`overflow: hidden; touch-action: none`)** — *spectacle-only, highest cost.* Deletes scrolling, find-in-page, and keyboard navigation for the whole document. Acceptable only when the canvas is the entire product *and* an accessible alternative exists at another URL.
- **Monospace-only, single-weight type** — *production-safe, recommended* — **provided the type is real DOM text.** The register is worth stealing; the rasterization is not. Two mono families at one weight, differentiated by optical density, is a legitimate and cheap system.
- **Single-hue luminance hierarchy** — *production-safe, recommended.* Costs nothing and improves focus. Verify AA contrast independently: a luminance-only palette makes it very easy to ship 2.9:1 text without noticing.

## Extracted patterns

- `blueprint-assembly-preloader` — a load sequence that draws the subject as an annotated wireframe, then resolves it into the finished render, so an unavoidable asset wait becomes the page's most memorable beat; reuse for 3D heroes, configurators, map viewers, or any hero image worth introducing rather than fading in.
- `clear-color-canvas-shell` — the full-viewport canvas page shell done correctly: the renderer's clear color hoisted into a CSS variable that paints the document (no load flash), gesture capture gated to fine pointers, and a real, selectable DOM text layer plus a static poster underneath so the page still works with no JS, no WebGL, or reduced motion.
