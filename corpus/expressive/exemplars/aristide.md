## What works (transferable principles)

- **Pick a desaturated *tint* as the foreground instead of white-on-black.** Every mark on the page is a muted sage-grey `#bac4b8`, not `#fff`, sitting on near-black `#1e1e1e`. The near-match in value (low contrast, ~5:1 not 21:1) makes the whole interface feel hushed, filmic, and considered — pure white would feel like a default terminal. Mechanism: choosing the ink color is a design decision, and a slightly-off neutral signals authorship the way pure black/white never can. Transfers to any dark UI that wants a mood (editorial, luxury, instrument) — shift fg a few degrees off white into a brand-adjacent grey and the entire page re-tones for free. Cost: you must still clear WCAG, so tune the tint to keep ≥4.5:1 on body text.

- **Anchor the one hero object to an edge and let it bleed off, rather than centering it.** The portfolio is a single horizontal row of tall portrait slats pinned to the right and running *past* the viewport edge, with the left two-thirds left empty. An off-center, clipped object reads as "this continues — there's more, drag to see it" far better than a centered, fully-contained gallery, which reads as finished. Mechanism: a cut edge implies an off-screen continuation, creating latent density and an invitation to interact without any "scroll" affordance. Transfers to any showcase where you want to imply a larger set behind a small visible slice (carousels, archives, feeds).

- **Use scale and value as the *only* hierarchy tools — never weight.** The entire site is a single 400 weight. The giant condensed wordmark dominates by size; the chrome recedes by being tiny and lower-contrast; "ABOUT" is promoted only by an underline. Removing weight from the toolkit forces a cleaner, more deliberate composition and gives the one display moment all the air. Mechanism: when everything is the same weight, the eye orders by size and brightness, which reads as calm and intentional. Transfers to any minimal system — commit to one weight and let scale + value (and rare underline) do all the ranking.

- **A heavily *condensed* display face is a complete identity in one word.** "ARISTIDE" in a tall, compressed grotesque needs no logo, no tagline, no mark — the extreme horizontal compression *is* the brand. Condensing lets a long word read at huge size in a narrow column and gives it a fashion/editorial register a normal-width sans can't. Mechanism: distort one axis (width) of a single word and it stops being text and becomes a logotype. Transfers to wordmark-only brands; derive the rest of the UI's restraint *from* that one loud word so it stays the sole focal point.

- **Replace decorative chrome with a tiny technical *readout*.** Centered in the top bar sits a row of monospace tick marks (`||||||||`) — an ambient scrubber/progress glyph that says "interactive system running" without a label, icon, or animation cost. Borrowing instrument iconography (ticks, dimensions, status lines) signals craft and machinery before any content loads. Mechanism: a precise, monospaced micro-element reads as a gauge, implying a live system behind the page. Transfers to any product wanting a technical/precise character — a single tabular readout outperforms a decorative flourish at a fraction of the weight.

- **Frame the empty stage with corner-anchored metadata, not a header band.** Identity top-left, nav top-right, status ("INDEPENDENT DEVELOPER / AVAILABLE APR. 2023") bottom-left, contacts bottom-right — all tiny, tracked, same sage. Pushing apparatus to the four corners keeps the optical center free for the hero object while still carrying full information. Mechanism: hierarchy by *position* (center = subject, corners = controls/meta). Transfers to any spectacle hero that must also carry nav + status without a chrome bar competing with the work.

## Design-system read
- **Type:** Two families, two jobs. A **heavy condensed display grotesque** (raw alias `jws`) carries the single giant wordmark (~337px, raw, with ~-0.05em / raw `-8.1px` tracking); a **tabular monospace** (raw alias `TNY`) carries the tick-readout and every micro-label (10–12px, ~+0.2px tracking). *Tracking grades bigger=tighter — but note the per-size table `.craft.type_detail.tracking_by_size` came back **empty**, so these two endpoints are read from the raw `letterSpacing` frequency list, not a captured size→tracking curve.* Hierarchy is pure **scale contrast** in one weight: ~10px chrome jumps to a ~337px display word (a ~30× ratio), so size alone ranks everything. **No bold** exists anywhere (single 400). Promotion of a link = underline, not weight.
- **Color:** Monochrome **tint-on-near-black**. `fg` is desaturated sage `#bac4b8` (the dominant computed color), `bg` near-black `#1e1e1e`, with `muted` an opacity drop of the same sage. There is **no chromatic accent in the chrome** — `accent` aliases the sage fg. The rainbow of hues in the raw profile (pink/gold/green/purple/red) are per-project case-study accents / WebGL output and are *not* part of the system. Imagery is desaturated B&W.
- **Spacing rhythm:** ~8px base, but the operative values are a consistent **30px chrome inset** from every edge (raw paddingInline 30px) and large vertical voids framing the centered/edge-bleed strip. Bimodal: tight inside label groups, vast around the single hero object.
- **Layout system:** No visible column grid — a **corner-anchored frame** (wordmark TL, nav TR, status BL, contacts BR, tick-readout top-center) wrapping an off-center hero. Desktop: tall slats pinned right, bleeding off-edge, left two-thirds empty. Mobile: a smaller slat strip centered mid-page with a faint left/right edge **mask** (fade), chrome stacked top, contacts stacked bottom. Two breakpoints of consequence (desktop edge-bleed → mobile centered-masked).
- **Motion / easing intent:** The only authored CSS transitions are `0.5s` with easings `ease` and `cubic-bezier(0.25,0.46,0.45,0.94)` (easeOutQuad) — gentle, decelerating, never bouncy (raw `params`: `durations_ms:[500]`, `easings:["ease","cubic-bezier(0.25,0.46,0.45,0.94)"]`). The signature motion (horizontal drag-scroll inertia across the slats, per-thumbnail WebGL hover/reveal) is JS/GL and absent from computed styles — it surfaces only as a persistent `requestAnimationFrame` loop (604 rAF calls in one capture) feeding 2 `<canvas>` nodes, plus 1 `mousemove` listener. Intent: weighty, smooth, "a heavy object settling" rather than snappy UI. Full breakdown + per-technique safety in **Interaction & motion** below.
- **Density:** Very low surface density — one word, one slat strip, a few corner labels. Latent density (a full project set off the right edge, an About page, case studies with their own color) is deferred off-screen. The hero buys attention with emptiness.
- **Hierarchy:** Dominant device is **scale**, reinforced by **value** (bright sage vs dim chrome) and **position** (center = stage, corners = meta). Weight and color are deliberately not hierarchy tools.
- **Restraint:** No white (a tint instead), no bold, no second hue in the chrome, no shadows, no radius, no header/footer bands, no buttons (links + one underline), no centered hero. Everything loud is the wordmark and the strip; everything else whispers in the same grey.

## Interaction & motion

This is a **WebGL/pointer-driven instrument, not a scroll-choreography page** — the inverse of teak. The capture is unambiguous: **0 `@keyframes`, 0 CSS animation rules** (`keyframeCount:0`, `cssAnimationRules:0`), **no IntersectionObserver** (`usesIntersectionObserver:false`, 0 targets), **no scroll listeners**, and only **1 scroll effect** — a single `pin (fixed)` on the project-viewer `main`. All the life comes from **2 `<canvas>` nodes** driven by a **persistent `requestAnimationFrame` loop (604 rAF calls in one pass)** plus **1 `mousemove` listener**; no library globals were detected (hand-rolled GL/JS). **Note: the four scroll frames (s00=s03=s06=s09) are pixel-identical** — the page is a fixed single-screen stage whose motion is *drag* and *hover*, neither of which a scroll-stepped capture can show; motion below is therefore grounded in probe counts + the pinned-`main` DOM + the corner readout, not in the frames, and the recorded `entrance` spans (`1.00→1.00` on the index digits) are dropped as `from==to` noise. **`prefers-reduced-motion` is NOT respected** (`prmRules:0`, `reduced_motion:false`) — the single biggest liability, doubly so because the *only* way to browse the work is through the animated GL strip.

- **Inertial drag-scroll across the slat strip** — *Trigger:* drag / pointer (the strip is the primary navigation; `mousemove` listener + the 604-call rAF loop integrate momentum). *Mechanism:* pointer velocity ← drag → the horizontal offset of the edge-bleed portrait row eases out under simulated friction (the authored `easeOutQuad`/`ease`, 500ms feel), so the row keeps gliding and settles like a heavy object rather than snapping. *Reads as:* a weighty, filmic gallery you *push* — tactile and considered, matching the hushed sage palette. *Transfers to:* any horizontal archive/carousel where heft and "drag to explore" are the point. *Safety:* **spectacle-only** — it augments/hijacks native scroll (motion-sickness + a11y), runs a continuous main-thread/GPU rAF loop, and does nothing for keyboard or reduced-motion users. Gate behind `prefers-reduced-motion` + a fine-pointer check, and back it with a real focusable, natively-scrolling `overflow-x` row of links. *(No exact recipe — `patterns_to_build: inertial-drag-strip`; the static layout is `edge-bleed-portrait-strip`.)*
- **Per-thumbnail WebGL hover/reveal** — *Trigger:* hover / pointer (fed by the same `mousemove` + rAF; `hoverEffects:0` in CSS confirms it is GL, not a CSS transition). *Mechanism:* cursor position ← pointer → a shader on the 2 `<canvas>` layers warps/un-desaturates the hovered slat (displacement / reveal), so a B&W slat resolves toward its image under the cursor. *Reads as:* the work "wakes up" where you point — craft signaling a live rendering engine behind the still. *Transfers to:* portfolio/gallery thumbnails wanting a tactile, premium hover beyond a CSS fade. *Safety:* **spectacle-only** — shader + continuous rAF is a real GPU cost and invisible to crawlers/reduced-motion; ship a plain `filter: grayscale()`→none CSS hover as the floor. → related: `webgl-thumbnail-sphere` (GL-thumbnail technique), `inset-canvas-stage` (canvas-as-stage framing).
- **Pinned project-viewer (case study)** — *Trigger:* click → scroll-progress (the one captured scroll effect: `position` → `pin (fixed)` on `main "…house of Gucci COMPLETED FEBRUARY…"`). *Mechanism:* selecting a slat fixes the project view to the viewport (`position: fixed`) with its index counter + metadata while content moves beneath, i.e. native sticky/fixed, no per-frame JS. *Reads as:* a stable stage on which one project performs — scrollytelling for the case study. *Transfers to:* detail/case-study overlays on a portfolio. *Safety:* **production-safe** (native fixed positioning, no rAF). → `sticky-pin-scrollytelling`.
- **Index/counter readout** — *Trigger:* drag/selection state (the `span "0"/"1"` digits the capture logged as "entrance"; ground truth = a live counter, not an entrance animation). *Mechanism:* current-item index ← strip position → a monospace digit pair updates as you move through the slats, pairing with the top-center tick glyph. *Reads as:* an instrument's position gauge — "you are at item N of the set." *Transfers to:* any drag gallery wanting a precise, low-cost position cue. *Safety:* **production-safe** (text swap; expose the value to assistive tech rather than leaving it decorative). → `tick-scrubber-indicator`.
- **Gentle UI hover transition** — *Trigger:* hover (the lone authored CSS transition: `0.5s`, `ease`/`cubic-bezier(0.25,0.46,0.45,0.94)`). *Mechanism:* `opacity`/underline on the corner links (ABOUT, EMAIL/INSTAGRAM/TWITTER) eases over 500ms — slow for chrome, which reads as deliberate rather than snappy. *Reads as:* the same "heavy settle" character applied to micro-UI; nothing bounces. *Transfers to:* minimal/editorial chrome where you want unhurried, low-key feedback. *Safety:* **production-safe** (compositor/opacity; 500ms is long for a hover — fine on text links, would feel laggy on primary actions).

## Production-safety note
- **Tint-as-foreground (sage `#bac4b8` on `#1e1e1e`)** — **production-safe** and recommended. Cost: contrast. An off-white tint lowers contrast vs pure white, so verify body/label text clears WCAG AA (4.5:1) against the *actual* near-black; the giant wordmark is large-text (3:1) and has margin, but 10px micro-labels are the risk — measure them.
- **Edge-bleed off-center hero strip** — **production-safe** as layout. Cost: the off-screen items must remain reachable — the horizontal region needs real keyboard/scroll access and a visible affordance for users who won't guess to drag (a focusable scroll container, or arrows). The *clip* is free; the *only-draggable* interaction is the a11y risk, so back it with native overflow scrolling.
- **Single condensed display wordmark at ~337px** — **production-safe** on desktop but **needs a responsive `clamp()`**: a giant fixed word overflows narrow viewports, and condensed faces lose legibility when scaled down hard. Clamp size and gate the heavy negative tracking to large sizes only.
- **Monospace tick-scrubber readout** — **production-safe**. Negligible cost (text). Mark it `aria-hidden` if purely decorative, or wire it to a real value (scroll position / item index) and expose that to assistive tech; don't leave a meaningless glyph announced to screen readers.
- **Corner-anchored metadata frame** — **production-safe**; pure positioned text, fully responsive (each corner collapses independently to a stacked layout on mobile, as the capture shows).
- **Drag-scroll inertia + per-thumbnail WebGL hover/reveal** — **spectacle-only.** Cost: hijacks/augments native scroll (motion-sickness + a11y), janks on low-end GPUs, and is invisible to crawlers and reduced-motion users. Gate behind `prefers-reduced-motion` + a capability check; the strip must work as a plain, focusable, natively-scrolling row of links without it.
- **Desaturated B&W imagery** — **production-safe** stylistic choice; just author it server-side/with `filter: grayscale()` and keep `alt` text describing the real subject, not "greyscale photo."
- **A11y, measured (honest defects):** the capture shows real gaps to fix before reuse. **(1) Reduced motion is NOT respected** (`reduced_motion:false`, `prmRules:0`) — and because the *only* path to the work is the animated GL strip, a reduced-motion user gets no accessible browsing path; this is the headline defect. **(2) Focus visibility fails** (`focus_visible:false`): the one probed action (`a EXPLORE`) draws a `1px rgb(16,16,16)` outline — near-black on the near-black `#1e1e1e` ground, i.e. invisible; ship a sage/high-contrast `:focus-visible` ring instead. **(3) Tap targets:** 14 elements flagged small (`small_tap_targets:14` of `interactive_count:47`) — the tiny tracked corner labels and the slats need ≥44px hit areas on touch. **(4) Good news:** `img_alt_ratio:1` — every one of the 20 images has alt text. Net: the *aesthetic* tokens (tint-on-near-black, condensed wordmark, corner frame) are production-safe; the *interaction model* (GL strip, no reduced-motion path, invisible focus) is the part that must be re-engineered for a shipping product.
