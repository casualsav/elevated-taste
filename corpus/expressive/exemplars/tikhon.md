## What works (transferable principles)

- **One typeface carries the entire identity.** A single bitmap monospace (PP Neue Bit) in essentially one size and one weight does all the work — no serif/sans pairing, no weight ladder. The concept (a printed receipt) supplies the personality, so the font only has to be *consistent*. Transfers anywhere you want strong character on a near-zero asset budget: pick one opinionated face, commit fully, and let structure (not styling) create interest.
- **A real-world metaphor replaces a visual hierarchy.** The page is structured as an invoice/receipt — ORDER #, dated header, numbered line-items, column headers (#, NAME, YEAR), a "THANK YOU FOR YOUR VISIT" total. Readers already know how to scan a receipt, so the familiar schema *is* the navigation; you don't need size jumps to signal importance. Transfers to any content that maps onto a known document type (ledger, boarding pass, spec sheet, changelog, terminal log).
- **Tabular columns + monospace = legible density for free.** Because every glyph is the same width, numbers and dates line up into clean columns with no manual alignment, and CSS `tabular-nums` isn't even needed. You can pack a lot of rows (projects, talks, lectures, press) and they stay scannable. Transfers to data-dense lists, pricing, specs, and changelogs — monospace is an honest, low-effort path to a tidy grid.
- **Hierarchy from inversion and dividers, not scale.** With body text nearly uniform (≈22px everywhere), emphasis is created by (a) two inverted black bars — the wordmark at top and the "THANK YOU" footer — and (b) thin full-width rules separating each section. Two contrast registers (black-on-white body, white-on-black anchors) bookend the page and frame the calm middle. Transfers as a restraint technique: reserve inversion for 1–2 anchor moments instead of scaling type up everywhere.
- **A single liquid/distortion accent earns its keep against a flat field.** The only "effect" is the wavy displacement on the wordmark glyph. On an otherwise rigid, flat, monochrome page one moving/warped element reads as expensive and intentional rather than noisy. Transfers as a rule: in a deliberately plain system, one signature animation is worth more than ten.
- **Uppercase + generous letter rhythm signals "system / document," not "marketing."** Setting labels and headers in uppercase monospace makes the page feel like machine output (an order confirmation), which suits an engineer-designer's positioning. Transfers when you want a technical, credible, anti-glossy tone.

## Design-system read

- **Type:** Effectively a *single-step* scale. Body ≈22px / line-height 18px (tight, set below the em for a printed, condensed feel) dominates ~88% of nodes; two display sizes (~48px, ~60px) appear only in the wordmark and the "THANK YOU" footer. One bitmap-monospace family at weight 700, a fallback system-sans at 400/16px for fine print. Hierarchy is structural, not typographic.
- **Color:** Two colors. `bg` pure white `#fff`, `fg` pure black. Inverted roles (`fg-invert` white on `accent-strong` black) used only for the wordmark bar and footer block. No hue, no semantic palette — maximum contrast, AAA by default.
- **Tracking:** Per-size tracking was **not captured** (`type_detail.tracking_by_size` is empty), so the apparent "letter rhythm" is the monospace face's native advance plus uppercase setting — not an authored letter-spacing ramp. Read the spacing as a property of the font + caps, not a tuned token.
- **Spacing rhythm:** Tight 4px base. Common values cluster at 6/8px (row padding, inline padding) for dense ledger rows, with larger 20/24/32px breaks between major sections. Whitespace separates the receipt's "blocks"; within a block, rows are packed.
- **Grid / container:** A single narrow centered column (the receipt strip, **measured ~500px wide** on a 1440 viewport — `max-width: 500px`, the genuine content column here) floated on a black field. The raw profile reports a **3-track** container (`grid.columns: ["3"]`) — frame-corroborated as the desktop three-zone header band (`DESIGN` · center `⚖` · `ENGINEERING`) and the dotted-grid margins flanking the strip; line-items themselves are 2-column `space-between` (label / year), not grid cells. Notably this `3` does **not** collapse on mobile (raw `grid_collapse` is `["3"]` at both 1440 and 390) — the layout is the same receipt at every breakpoint.
- **Layout system:** Single narrow centered column (a receipt strip) on both desktop and mobile — the desktop just adds dotted-grid margins and DESIGN | ENGINEERING flanks. Two-column line-items (label left, year/qty right) via space-between. Essentially the *same* layout at every breakpoint, which is why it survives mobile untouched.
- **Motion / easing intent:** Sparse and ambient, not a scroll choreography. Captured params are just two durations — **1000ms** (the long liquid-wordmark distortion) and **500ms** — on the bare `ease` curve (no explicit cubic-bezier, no stagger). The only declared `@keyframes` is `displace` (the wordmark warp); there are **0 hover effects** and **0 cursor-followers** in the probe. What *runs hot* despite the calm static read is a **pointer-reactive ASCII glyph field** in the margins (9 `mousemove` listeners, 2 `<canvas>`, ~235 rAF/scroll) plus a fixed backdrop layer. Motion is decorative-signature + ambient texture, never functional/wayfinding. Full per-technique breakdown, evidence, and safety in **Interaction & motion** below.
- **Density:** High line-item density kept legible by monospace alignment, uppercase labels, and rules between sections — the eye uses the table structure to chunk.
- **Hierarchy:** Dominant ordering device = **position + structure** (receipt schema), with **inversion** as the only emphasis lever. Scale and weight are nearly flat by design.
- **Restraint:** No imagery, no color, no gradients, no shadows, no multi-weight type ramp, no second font for headings. The discipline of "one font, two colors, one effect" is the whole point.

## Interaction & motion

Tikhon's motion is **the inverse of teak's spectacle**: there is no scroll choreography on the *content* — the receipt simply scrolls (frames s00→s09 show the strip translating straight up, header → tables → perforated bottom edge + "THANK YOU FOR YOUR VISIT", with **nothing pinned, recolored, scaled or parallaxed in the document column**). All the motion lives in two ambient, decorative layers around the flat page. Evidence from the capture: only **2 scroll effects** (1 `pin (fixed)`, 1 `filter` on the wordmark), **1 `@keyframes` (`displace`)**, **2 `<canvas>`**, **9 `mousemove` + 3 `scroll` listeners**, **~235 rAF/scroll**, **1 IntersectionObserver over 0 targets** (so IO is effectively unused), **0 hover / 0 cursor-follower** effects, **0 detected libraries** (hand-rolled). **`prefers-reduced-motion` is NOT respected** (`prmRules: 0`, `a11y.reduced_motion: false`) — the headline liability. Stack: SVG `<filter>` displacement-map · `<canvas>`/DOM glyph field · CSS `@keyframes` · `position: fixed` backdrop. The frames *captured the static layout well* but could not show the wordmark warp or the per-frame glyph drift as motion — those are grounded below in probe counts + the `displace` keyframe + the `#displacementFilter3` markup, not in frame-to-frame deltas.

- **Liquid displacement wordmark** — *Trigger:* load + continuous (the `displace` keyframe; a 1000ms `ease` transition). *Mechanism:* an SVG `feDisplacementMap` (`filter: url(#displacementFilter3)`) warps the masthead glyphs; in s00 the center of "TIKHON BELOUSKO" is pulled into a visible liquid spiral/vortex while the outer letters stay legible. *Reads as:* one expensive, signature gesture on an otherwise rigid flat page — "this plain thing is alive and intentional." *Transfers to:* a single wordmark/logo/hero glyph in a deliberately minimal system (one signature beats ten). *Safety:* **spectacle-only** — SVG-filter displacement is GPU-heavy, can jank on low-end devices, warps the logo past glyph/brand recognition, and (animated) ignores reduced-motion. Gate behind `prefers-reduced-motion`, keep an undistorted accessible name. No corpus recipe → see `patterns_to_build`. (The static read already flagged this as the lone effect; this is its mechanism.)
- **Pointer-reactive ASCII glyph field** — *Trigger:* pointer (9 `mousemove`) + ambient rAF (~235/scroll), painted on 2 `<canvas>`. *Mechanism:* a scattered field of repeated `%` glyphs fills the black margins flanking the receipt; across frames s00→s09 the clusters visibly change position and density (denser top-right in s00, drifting/reflowing lower and left by s06/s09), i.e. a particle field that responds to pointer movement and animates per-frame rather than a static texture. *Reads as:* machine-output "noise" / printer static framing the receipt — ambient brand texture, never a message. *Transfers to:* decorative margin/hero fields in expressive layouts where you want living texture around calm content. *Safety:* **spectacle-only** — continuous rAF + canvas + `mousemove` is an ongoing CPU/battery draw, does nothing useful on touch, is meaningless to assistive tech (must be `aria-hidden`), and is exactly the flourish to drop first under a perf or reduced-motion budget. → `ascii-particle-ring` (DOM/canvas repeated-glyph field that scatters/recomposes on pointer + scroll).
- **Fixed backdrop layer** — *Trigger:* scroll-progress (the single `pin (fixed)` effect on `div.fixed`). *Mechanism:* a `position: fixed` layer (the dotted-grid margin field / glyph backdrop) holds still in the viewport while the receipt strip scrolls over it, so the dotted grid and `%` field read as a stable stage and the receipt as a physical slip moving across it. *Reads as:* depth — paper sliding over a fixed printed surface. *Transfers to:* any minimal page wanting a persistent textured backdrop behind scrolling content. *Safety:* **production-safe** (native `position: fixed`, no per-frame JS for the pin itself — the cost is in the glyph field it carries, above). Note: this is a fixed *backdrop*, not scrollytelling — do **not** mistake it for `sticky-pin-scrollytelling` (no content is being narrated against a pinned anchor).

## Production-safety note

- **Receipt/ledger layout (the structure itself)** — **production-safe.** It's just semantic tables/definition-lists in a narrow column; fully responsive, accessible, prints beautifully. Reuse freely for portfolios, changelogs, specs.
- **Single bitmap-monospace at one size** — **production-safe with caveats.** Great character, but a bitmap/pixel font hurts readability at long-form body lengths and small sizes; fine for short labeled rows, risky for paragraphs. Always ship a real monospace fallback (already done here) and test at the smallest size. FOUT/FOIT on a hero-defining custom font is a perceived-perf cost — preload it.
- **Near-zero type-scale (flat ≈22px hierarchy)** — **spectacle-only as a global rule.** It works *because* the receipt metaphor carries meaning; in a generic product UI, removing scale contrast destroys scannability and a11y landmarks. Borrow the *idea* (let structure do hierarchy) but keep real heading levels in conventional UIs.
- **Liquid/displacement wordmark animation** — **spectacle-only.** Typically SVG filter / WebGL / shader distortion: GPU cost, can jank on low-end devices, and a warped logo can fail logo-recognition and (if animated continuously) `prefers-reduced-motion`. Gate it behind reduced-motion and keep an undistorted accessible name.
- **Full-page max contrast (pure #000 on #fff)** — **production-safe** for legibility/AAA; mild note that pure-black-on-pure-white can cause halation for some readers — a near-black (`#0b0d12`) is gentler with no perceptual loss.
- **Pointer-reactive `%` glyph field** — **spectacle-only.** Continuous canvas + rAF + `mousemove` is an ongoing CPU/battery cost, inert on touch, and noise to assistive tech. Mark `aria-hidden`, pause off-screen, and drop it entirely under reduced motion.
- **A11y, honestly:** **reduced-motion is NOT respected** (`prmRules: 0`) — the page's main defect; the displacement warp and glyph field run regardless of the user setting. Mitigating positives: contrast is AAA (pure #000/#fff), there are no images so alt-text is N/A (`img_count: 0`), and links **do** get a focus outline (`1px rgb(16,16,16)` on all 8 captured links) even though the summary `focus_visible` flag reports false. Watch: **12 of 20 interactive targets are below the 44px tap minimum** — the dense receipt rows are small touch targets on mobile.
