## What works

- **Two-axis type system as the entire brand.** One compressed grotesque (NB International) carries every label, lead-in, nav item and body line; one Clarendon-Light slab serif is reserved for *names and voice* — the rotating hero word, project titles, city names, "Apply here". This is the inverse of the usual serif-body/sans-display split, and it reads as deliberate because the expressive face only ever appears on the thing being named. Transfers to any brand that wants editorial warmth without a third typeface: pick a workhorse and an accent, and assign the accent to nouns, not to size.
- **Whitespace, not boxes, does all the separating.** Zero corner radius, zero shadows, hairline rules only; sections are divided by very large vertical voids. At high item density (a 20+ project grid) the page still reads calm because each plate floats in air rather than sitting in a card. Transfers directly to content-dense product UI: remove the card, add the space.
- **Chroma is quarantined to the content.** The chrome is strictly greyscale — white, warm paper, near-black, two greys. Every saturated color on the page (pink, aqua, orange) lives *inside a project thumbnail*. The work supplies the color so the frame never competes with it, and swapping the work re-themes the page for free. Transfers to any gallery/portfolio/marketing grid where the media is the hero.
- **An asymmetric, vertically-offset grid signals "studio" instantly.** Three columns where neighbouring columns start at different heights and items vary in aspect ratio reads as hand-composed, not templated — the single most legible "this is a design studio" cue, achieved with CSS columns and no per-item placement. Transfers to any feed that wants to feel curated rather than generated.
- **The dark inset CTA as a single tonal breath.** After a long bright grid, one near-black full-bleed block with text parked low in a tall void resets the eye and stages the one conversion line ("Discover more"). One contrast register, used once, lands harder than scattered accent buttons. Transfers as a mid/late-page CTA device on otherwise light pages.

## Design-system read

- **Type:** Two families, two weights (300/400) only — no bold anywhere; emphasis is *family + size*, never weight. Grotesque workhorse sits at ~22px for nearly all UI/body; the Clarendon serif appears at display scale for the cycling hero word (~80–90px) and at ~22–23px for project/city names. Hierarchy ratio from body to display is roughly 4–4.5×. **Tracking is essentially neutral, not negative**: the only sample the capture exposes is `+0.3px` at 60px (`.craft.type_detail.tracking_by_size`) — a hair *open* rather than tightened, and the 80px `h1` reads `tracking:normal`. The serif stays light (weight 300/400) so the big word feels engraved by *contrast and size*, not by squeezed letter-spacing.
- **Color:** bg `#ffffff`, warm-paper surface `#f8f6f5` (footer), near-black inset `#191919`, ink text `#2c2d2e`, rules/muted `#c6c5c5`. Roles: bg / warm-surface / ink-fg / muted-rule / inverted-block. No accent in the chrome — "accent" is whatever the thumbnails bring.
- **Spacing rhythm:** 8px-ish base, but the story is the *macro* scale: 40–70px gutters and inter-item gaps, and section voids many hundreds of px tall (the CTA block carries ~660px of internal top-pad so its copy sits in the lower third). Whitespace is treated as a first-class element, not leftover.
- **Layout system:** Centered single column for hero and CTA copy; a three-column offset masonry for the work; a multi-column label/value grid for the footer (Work with us / inquiries / join / learn, then four office addresses). Desktop captured at 1440×900; mobile (390px) collapses every grid to one column and preserves the type contrast and rhythm exactly (`h1` downscales 80→40px; body holds at 22px both viewports). **Grid/container:** content sits in a **near-full-width ~1670px max-width container** (re-probed; the ~600px figure is the centered hero/CTA copy measure, not the page container). No CSS *grid* is exposed (`.craft.grid.columns:[]`, `layout.gridCols:[]` both empty) — the work feed is a CSS-`columns` masonry the static probe reads as no grid; **from s01/s03/s06 it is a 3-column offset masonry** (~40–70px gutters, columns starting at staggered heights, mixed aspect ratios). Hero/CTA copy sits in a centered single column. (Nav shows 0 links — a JS/canvas-driven hamburger the probe can't read.)
- **Motion / easing intent:** The only easing the capture exposes is the bare `ease` default at a single **1000ms** duration (`.motion.params`: `durations_ms:[1000]`, `easings:["ease"]`, no stagger delays) — this governs the slow cross-fade of the rotating hero word and the hover fades. Everything heavier is JS-driven per-frame via **GSAP (TweenMax)** (~2521 `requestAnimationFrame` calls in one scroll pass), so no explicit curves/durations are exposed for it. Note: the 3 `@keyframes` in the sheet (`vjs-spinner-show/spin/fade`) are **video.js loader chrome, not design motion** — the real choreography is all transform-driven JS, not CSS. Overall the motion reads "crafted", not "busy". Full per-technique breakdown, evidence, and safety in **Interaction & motion** below.
- **Density:** High item count, low perceived density — the grid holds 20+ projects but each is isolated by void, so it never feels like a list.
- **Hierarchy:** Dominant ordering device is **scale + typeface assignment**, supported by position; color and weight are deliberately not used to rank.
- **Restraint:** No bold, no radius, no shadows, no accent color in the UI, no gradients in the chrome. The only "loud" gestures (rotating word, corner sphere, color) are each used exactly once or quarantined to content.

- **Components** (from `.craft.states` — mostly **not captured**; this site is link-and-type-driven, not a component kit):
  - **Button:** **not captured** — there is no filled/pill button in the chrome; the only CTAs are text links ("Apply here", "Discover more") that get an underline, set in the slab serif. No hover/active/disabled button states recorded (`states.disabled:[]`).
  - **Card:** **none by design** — the system's whole thesis is *no cards* (zero radius, zero shadow, hairline + whitespace only); project plates are bare images on the page, so there is no card component to spec.
  - **Nav:** **not captured** as DOM (`navVisibleLinks:0`, `responsive.nav.likely_hamburger:false`) — navigation is the fixed hamburger glyph riding the WebGL sphere; no inline link bar to read states from.
  - **Input:** **not captured** — no forms on the captured pages (`states` exposes only link `focus`).
  - **What *is* captured — focus:** every interactive `<a>` takes a **`1px` solid `rgb(16,16,16)` outline** on `:focus` (8 of 8 sampled links) — a real, consistent **focus-visible ring** in near-black, the one well-built interactive state here.

- **A11y (honest):** **focus-visible — pass** (consistent 1px near-black `:focus` outline on every link). **Reduced motion — FAIL** (`a11y.reduced_motion:false`, `prmRules:0`): the cross-fade word, parallax, fixed WebGL sphere, and cursor-follower all run regardless of `prefers-reduced-motion` — the headline defect for an animated site. **Image alt — FAIL** (`img_alt_ratio:0` across 8 images): the project thumbnails — which carry *all* the page's meaning and color — appear to ship with no alt text, so the work is invisible to screen readers and the masonry's DOM-vs-visual order (CSS columns) compounds it. **Tap targets:** **4 small tap targets** flagged out of 52 interactive nodes — minor but real; keep link rows ≥44px on mobile. Net: chrome a11y is decent (focus ring, high ink contrast), but motion and alt-text are genuine, fixable defects.

## Interaction & motion

Hellomonday is an **agency portfolio that performs restraint**: where teak floods the viewport with ~5k rAF and 48 scroll effects, hellomonday spends its motion budget on a *very few* slow, deliberate gestures over enormous whitespace. The capture is hand-rolled on **GSAP (TweenMax)** — `~2521 requestAnimationFrame` calls in one scroll pass, **37 `IntersectionObserver`s over 37 targets** (every config identical: `threshold:[0,1]`, `rootMargin:200px` → plates are *preloaded 200px early*, not revealed on first pixel), 4 scroll + 4 `mousemove` listeners, 2 cursor-followers, 2 `<canvas>` + 3 `<video>`. Only **2 CSS animation rules / 3 `@keyframes`** exist and all three are `vjs-spinner-*` (video.js loader UI) — **the design motion is 100% JS transforms, zero meaningful CSS keyframes.** The captured scroll effects reduce to **2 transform/parallax** (the hero `h1` and an `img`) + **2 pinned/fixed** elements once the `opacity 1.00→1.00` no-op is dropped. **Critically, `prefers-reduced-motion` is NOT respected** (`prmRules:0`, `a11y.reduced_motion:false`) — the expected expressive-site defect, and the main liability here. Stack: **GSAP/TweenMax** · `IntersectionObserver` (preload) · `<canvas>`/WebGL · CSS transitions. Frames cited: `corpus/expressive/screenshots/hellomonday-com/frames/`.

- **Cycling hero word (cross-fade word-swap)** — *Trigger:* load + timer (the lone `1000ms`/`ease` transition). *Mechanism:* the static grotesque lead-in ("We make digital (and magical)…") holds while a single slab-serif noun cross-fades through the studio's disciplines (`opacity` over 1s, width reserved so the line never reflows). *Reads as:* a capabilities list compressed into one sentence read as both a thought and a slideshow — the one moving thing above the fold. *Transfers to:* studio/agency heroes, any "we do [X]" value line. *Safety:* **production-safe** *with care* — the word must be real text, width-reserved, and freeze on one meaningful noun under reduced-motion (which this site fails to do). → `cycling-word-headline`. **Frames did not capture the swap** — s00 shows only the resting word "Products"; the cycle is grounded in the 1s `ease` transition + the static read, not the stills.
- **Scroll-progress parallax on hero type + image** — *Trigger:* scroll-progress (the 2 surviving `transform/parallax` effects: `h1 "Products"` and an `img`). *Mechanism:* the display headline and a hero image translate at a rate decoupled from scroll, so the big serif word drifts against the field as you leave the top. *Reads as:* depth and intentional pacing — the type feels like a layer, not flat copy. *Transfers to:* any oversized display word or hero asset you want to feel dimensional on scroll-out. *Safety:* **production-safe if subtle** (compositor-only `transform`); the risk is doing it to the *headline you must read* — keep the drift small and never let it blur or out-run the eye. → `parallax-drift`.
- **Fixed corner WebGL sphere (off-canvas bleed)** — *Trigger:* load → continuous WebGL + one of the captured `pin (fixed)` effects. *Mechanism:* a near-black sphere bleeds off the **right edge** and holds `position:fixed` through the entire scroll — in every frame s00→s10 it sits at the same vertical anchor with the hamburger menu icon riding on it (~y450), while its curved silhouette subtly re-bulges frame to frame (WebGL redraw, fed by the 2 `<canvas>` + ~2.5k rAF). *Reads as:* a persistent dark "moon"/brand mark that frames the page without occupying layout — the studio's one spectacle gesture, used once. *Transfers to:* a single fixed brand-experience flourish on an otherwise austere page. *Safety:* **spectacle-only** — GPU/canvas + a JS bundle for one decorative, non-functional element that is invisible to crawlers/keyboards and ignored by this site's missing reduced-motion guard; gate behind capability + `prefers-reduced-motion` or drop it (the page works identically without it). Nearest recipe `webgl-thumbnail-sphere` covers the *WebGL-sphere-as-brand-object* principle, but it's a draggable **hero** sphere of thumbnails — the **fixed decorative corner-bleed variant here is not yet a recipe** (see `patterns_to_build`).
- **Scroll-revealed grid plates (IO-preloaded)** — *Trigger:* in-view, via the 37 identical IO configs (`threshold:[0,1]`, `rootMargin:200px`). *Mechanism:* project thumbnails in the masonry are lazy-mounted/faded as they approach the viewport, observed 200px early so media is ready before it's seen. *Reads as:* the work index "develops" as you descend. *Transfers to:* any long media/portfolio feed that must stay light on first paint. *Safety:* **production-safe only as progressive enhancement** — and **this very capture is the cautionary tale**: frames s01/s03/s06 show whole columns of *empty grey plates* because the reveal is JS-gated and content isn't present without it. Ship the resting (visible) state in the DOM and reserve aspect-ratio boxes so a JS stall doesn't blank the page. → `scroll-reveal-in-view` (use IO `threshold:0` + a one-shot CSS fade rather than a per-frame rAF loop).
- **Cursor-follower** — *Trigger:* mousemove (2 `cursor-follower` nodes fed by 4 `mousemove` listeners; captured as updating `matrix(…)` transforms, e.g. `matrix(0.5,0,0,0.5,10,6)→matrix(0.5,0,0,0.5,3,0)`). *Mechanism:* a small decorative element scales/lags toward the pointer on fine-pointer devices. *Reads as:* a quiet extra beat of craft for desktop visitors. *Transfers to:* brand-experience garnish only. *Safety:* **spectacle** — pointer-only (inert on touch), adds `mousemove` work, first thing to cut under a perf/reduced-motion budget; **not visible in the stills** (it only exists while the cursor moves). No corpus recipe — reuse the principle sparingly, fine-pointer-gated.

## Production-safety note

- **Two-axis grotesque/serif type system** — production-safe. Cost: two self-hosted font files (~two weights); enforce a fallback stack (raw shows `Georgia/Times` fallbacks already) and `font-display: swap`.
- **Whitespace-only separation (no cards/shadows/radius)** — production-safe and cheap; the main risk is tap-target spacing on mobile, solved by keeping link rows ≥44px.
- **Chroma-quarantine (greyscale chrome)** — production-safe; a discipline, not a technique. Free.
- **Three-column offset masonry** — production-safe via CSS `columns`. Cost/caveat: CSS columns fill top-to-bottom then wrap, so DOM order ≠ visual order — fine for a gallery, risky if reading order matters for a11y/SEO; use a real grid with explicit row-spans if order matters. Lazy-load images (as they do) and reserve aspect-ratio boxes to avoid layout shift.
- **Cycling hero word (animated word-swap)** — production-safe *with care*. Cost: the rotating word must be real text (not an image) and must respect `prefers-reduced-motion` (freeze on one word); reserve width so the line doesn't reflow as words change length, and ensure the resting word is meaningful for screen readers.
- **Corner WebGL sphere** — spectacle-only. Cost: GPU/canvas + a JS bundle for one decorative element; ships nothing functional. Gate behind reduced-motion and device capability, or drop it — the page works identically without it.
- **Scroll-driven plate reveals** — production-safe if (and only if) content is visible without JS and reveals are progressive-enhancement; otherwise the empty-plate failure mode in this very capture is the cautionary tale.
