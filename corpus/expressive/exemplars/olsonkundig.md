## What works
- **Scroll drives a *class*, not a *value*.** Six 100vh sections sit transparent over a stack of six `position: fixed` full-viewport video layers. As you cross a section threshold the script toggles a single `.fade-out` class; CSS then does all the work (`.home-screen > .wrap { transition: filter .8s linear }` → `filter: blur(3rem); opacity: 0`). Nothing is scrubbed per-frame, no property is interpolated against `scrollY`. This is the cheap way to build scroll-theater: **let scroll pick a discrete state and let CSS transition between states.** Transfers to any pinned-media narrative — you get the choreography of a scrubbed timeline with the cost profile of a hover effect.
- **A media stage that never scrolls.** The videos are fixed and z-ordered 6→1, matched to the statements by a `data-id` attribute counting down. The page *appears* to be six chapters; structurally it is one stage with six actors and a scrolling teleprompter. Because nothing translates, there is no parallax jitter and no reflow — only opacity and z-order change. Transfers to any "story over imagery" section where a naïve build would use six stacked hero images.
- **Contrast over unknowable video is manufactured, not hoped for.** White text sits over arbitrary moving footage, so legibility is engineered twice: every media layer is capped at `opacity: 0.875` against the near-black ground, *and* a directional `linear-gradient(to bottom left, transparent → rgba(24,18,19,0.618))` scrim is painted toward the corner where the copy lands. The header gets its own top-down gradient (`→ rgba(24,18,19,0.382)`, 50vh tall) so the wordmark survives a bright sky. The rule — **dim the media, then gradient toward the text, never the reverse** — beats a flat scrim, which kills the image everywhere to fix contrast in one corner.
- **The accent color is reserved for system state, never for brand decoration.** The palette is warm near-black (`#181213`), white, and three greys. The one saturated hue, a gold `#CC953D`, appears *only* as focus fill, as the motion-toggle's pulse ring, as the media player's control color, and as the error-modal ground. It is never a button, never a heading, never a hover. Scarcity is the usual accent lesson; the sharper one here is **which** scarcity: an accent spent exclusively on state means every appearance of it is information.
- **The whole page is one sentence per screen, with the CTA inside the sentence.** No buttons, no cards, no eyebrow labels. Each screen is a single 67px statement whose final clause *is* the link ("...founded on the unstable edge of the Pacific Rim. <u>Learn about our practice.</u>"), underlined with `text-decoration-thickness: 0.075em; text-underline-offset: 0.1em`. Nothing competes with the copy, so the copy has to be worth reading. Transfers to any brand-manifesto page where the temptation is a three-card value prop.
- **The footer is a permanent fixed underlay, not a destination.** `footer { position: fixed; bottom: 0; z-index: 0 }` sits beneath everything; the six statement sections are `background: transparent`, so the nav is faintly present at the bottom of the viewport the entire scroll (statement text literally overprints it in frames s00 and s05), and only the two opaque sections at the end (`#home-news`, `#last-screen`, both `steel-bg`) cover it — until the document runs out and the footer is simply *there*, fully lit. No slide, no reveal animation. Transfers anywhere you want a footer to feel like the floor of the page rather than a slab appended to it.
- **Optical alignment at display scale, done with a negative margin.** Display headings carry `header-adjust { margin-left: -0.0618em }` — the first glyph's left side-bearing is pulled back so the *ink*, not the box, aligns to the column edge. At 67px that side-bearing is a visible ~4px indent. A one-declaration fix most sites never make.

## Design-system read
- **Type:** InterVariable, single family, essentially two weights (300 for everything, 500 for micro-labels/uppercase). Sizes: 13 · 15 · 16 · 17 · 23 · 48 · 67px — a ~3.9× range from body (17px) to display (67px), *bimodal* rather than modular: 306 nodes at 17px, 9 at 67px. Hierarchy is pure **scale**; the weight axis is almost unused. Leading is a single ratio — body `23.494/17 = 1.382`, secondary `31.786/23 = 1.382` — dropping to `1.0` at display (67/67). Sizes step at breakpoints as percentages (`h1 { font-size: 223.5% }` → `394.1%`); no `clamp()`, no fluid type.
- **Tracking:** the opposite of the usual ramp — a **flat, positive `0.01em` (0.17px @ 17px) applied at every size, display included.** Where a grotesque normally wants negative tracking as it grows, Inter's optical sizing already tightens, and the site instead corrects the *left edge* with `margin-left: -0.0618em`. Uppercase micro-labels (13px, weight 500) get `text-transform: uppercase` and their own `letter-spacing: 0.01em`. Worth copying only if you're on a variable font with optical sizing; otherwise keep the negative-tracking ramp.
- **Color:** a named ladder, all warm-neutral: `steel #181213` (ground — deliberately *not* `#000`, a red-shifted near-black that keeps skin tones and timber in the photography from going cold), `white #fff` (fg), `mist #eeecec` and `sand #F7F7F2` (light surfaces for menu/search overlays), `concrete #75716E` (muted/disabled), `dark-concrete #3B3735` (player chrome), `timber #CC953D` (state accent only). Every scrim and overlay is `rgba(24,18,19,α)` — the ground color at reduced alpha, never a generic black — which is why the dimmed video reads warm rather than muddy. Alphas are golden-section constants (`0.125 / 0.382 / 0.618`).
- **Spacing rhythm:** 15px base, doubling — 15 / 30 / 60 (31 elements at `padding-inline: 30px`, 23 at `padding-block: 30px`, 6 at 60px, gaps 15/30). Above that the rhythm is not spacing at all but **the viewport**: sections are `height: var(--fillLVH)` with `max-height: var(--fillSVH)` (a correct mobile-URL-bar fix, with a `--vh`/`--winHeight` JS fallback). Whitespace is enormous and structural — a statement occupies the bottom-left ~35% of a screen and the other 65% is stage.
- **Layout system:** a viewport-relative column system, not a container: `--column-width: calc((100vw - var(--gutter)) / var(--columns))` with `--columns: 12` (landscape) / `6` (portrait) / `3` (≤767px), `--gutter: 3rem` → `1.5rem`. Layout is 38 flex contexts to 1 grid — flow, not grid. Measured text containers: 1087.5px and 852.5px on a 1440 viewport; everything else is `100%`/full-bleed. Copy is bottom-left aligned to the gutter on both desktop and mobile — no centering anywhere. Breakpoints are numerous (480 → 2560 min-width, plus `orientation` and `min-height` queries, because the layout is height-driven).
- **Layering / page architecture:** this is the exemplar's real subject. **21 fixed elements, 1 sticky, zero blend modes, zero backdrop-filters** — depth is built entirely from z-order and opacity. Bottom to top: `footer` (fixed, z0) → `.home-videos` (fixed, full-viewport, z0, `opacity: 0.875`) → six `figure.section-image.fixed` media layers (z6…z1, one `.playing`, rest `.paused`) → the scrolling document (`#content`, 8100px tall, **92% of its surface area transparent** — 9 of 11 blocks) → `header` (fixed, z9, transparent, with a gradient pseudo-element) → menu/search overlays (z5–6, `opacity: 0`, `visibility: hidden` until opened) → `#to-top` (z100) → `#reduced-motion-notice` (z999). The content plane has no background of its own; it is a sheet of glass with type on it, sliding over a fixed cinema. Only `#home-news` and `#last-screen` are opaque, and that is what lets the ending land.
- **Motion / easing intent:** three durations — `200ms` (micro-feedback, 43 uses), `400ms` (state crossfades, 24 uses), `800ms` (the blur dissolve, 7 uses) — and the dominant easing is **`linear`**, not a curve. That is correct and deliberate: opacity/filter crossfades read as light, not as movement, and an ease on a crossfade makes it feel like a swipe. Curves are reserved for things that actually travel (`cubic-bezier(0.55,0.055,0.675,0.19)` = easeInQuint on heights, `cubic-bezier(0.4,0,0.2,1)` on the search box). The `visibility 0s linear .4s, opacity .4s linear` idiom recurs 6× — the layer fades out *then* leaves hit-testing and the a11y tree, which is the accessible way to hide an animated overlay.
- **Density:** near-zero. One sentence per 900px screen; ~10 headings on the entire homepage. The information density lives in the media, and the media carries no chrome. This only works because the copy is short enough to be read at a glance while a video plays behind it — the constraint *is* the design.
- **Hierarchy:** scale first (17px → 67px, one weight), position second (everything anchors bottom-left to the gutter), color third (white vs. `concrete` grey for the underlay chrome). No boxes, no rules, no shadows do any ordering work.
- **Restraint:** zero border-radius except the 1em motion-toggle dot. Zero box-shadow except the toggle's pulse ring. Zero `mix-blend-mode`, zero `backdrop-filter`, zero `@keyframes` in the site's own CSS besides `motion-pulse`. No cards, no buttons on the homepage, no hover effects at all (`hoverEffects: 0` measured). Every effect in the build is opacity, z-index, blur, or `translateY` on the header.

## Interaction & motion

Olson Kundig is a **scroll-theater built almost entirely out of class toggles**. The probe is unambiguous about the shape: `32` scroll effects of which `11` are `pin (fixed)`, `9` opacity, `6` `filter`, `6` transform; **`0` IntersectionObservers**, `3` scroll listeners, `1503` rAF calls (the six autoplaying Vimeo videos, not DOM animation); **`0` `@keyframes` in the site's own stylesheet apart from `motion-pulse`**, `0` libraries detected for the choreography (Slick.js drives only the project carousel). Frames `s00`–`s10` corroborate: `s01` and `s02` caught two statements *mid-dissolve*, rendered as a legible-shape-turned-smear — that is `filter: blur(3rem)` transitioning over `800ms`, not a fade. `s07` shows the carousel with its `1 / 8` counter; `s10` shows the fixed footer finally uncovered, its motion-toggle dot lit white.

- **Fixed media-stack crossfade** — *Trigger:* scroll-progress (threshold → class). *Mechanism:* six `position: fixed; inset: 0` media layers z-ordered 6→1, each bound to a statement section by `data-id`; entering a section plays its layer and applies `.fade-out` (`opacity: 0; visibility: hidden` after `400ms`) to the one above. No transform, no scrub. *Reads as:* the room changes around you while you stand still — the architectural metaphor made literal. *Transfers to:* any manifesto/chapter page where the temptation is six stacked full-bleed heroes. *Safety:* **spectacle-only** — six simultaneously-decoding videos is the cost, not the CSS; the layering itself is free. Poster-first, play only the active layer, pause the rest. → `statement-blur-dissolve-stage`
- **Blur dissolve on statement exit** — *Trigger:* scroll-progress (class toggle). *Mechanism:* `.home-screen > .wrap { transition: filter .8s linear }`; the leaving screen gets `filter: blur(3rem); opacity: 0`. Smaller chrome (arrows, slide counter) uses a lighter `blur(1.5rem)` plus `translateY(-6rem)`. *Reads as:* the sentence going out of focus, like a rack-focus pull in film — it defers to the image rather than sliding away. *Transfers to:* any exit transition where "slide up + fade" has become the house cliché. *Safety:* **spectacle-only.** `filter: blur()` is a raster operation, not a compositor property: a full-viewport blurred text layer costs a repaint per frame for the 800ms window. It is affordable *here only because it fires once per screen as a discrete transition* — the same effect scrubbed against scroll position would jank. Never blur an element that stays on screen. → `statement-blur-dissolve-stage`
- **Fixed footer as underlay** — *Trigger:* none (static layering). *Mechanism:* `footer { position: fixed; bottom: 0; z-index: 0 }` under a content plane that is 92% transparent by area; only the last two sections carry an opaque `steel-bg` and occlude it. *Reads as:* the page has a floor that was always there, rather than an ending that was appended. *Transfers to:* any long page wanting a grounded footer with zero JS. *Safety:* **production-safe.** One caveat the site does not solve: because the footer never leaves the viewport, its links overlap the statement copy in the lower-left (visible in `s00`, `s05`) — legible only because the footer sits at `concrete` grey. Give the underlay text a low-contrast resting state or the collision reads as a bug.
- **Retracting header with a gradient scrim** — *Trigger:* scroll-direction. *Mechanism:* `.move-up:not(header:hover) { transform: translateY(-6rem); transition: all .2s linear }` — the bar leaves on scroll-down and returns on scroll-up *or on hover*, which is the detail worth stealing (a retracted header that comes back when you reach for it needs no scroll-up gesture). `header::before` paints a `50vh` top-down gradient to `rgba(24,18,19,0.382)` so the wordmark survives whatever video is behind it. *Reads as:* chrome that gets out of the way without disappearing. *Transfers to:* any media-backed page with a transparent nav. *Safety:* **production-safe** (transform-only; the scrim is a pseudo-element with `pointer-events: none`).
- **Per-letter wordmark entrance** — *Trigger:* load. *Mechanism:* the logo is inline SVG with one `<path data-letter="…">` per glyph; each path fades `opacity 0 → 1` starting at ~150ms with `400ms`/`800ms` stagger delays (10 entrance reveals, `staggeredEntrance: true`). *Reads as:* the practice's name being drawn rather than dropped in. *Transfers to:* a brand mark you can afford to inline as SVG. *Safety:* **production-safe** — but the `<h1>Olson Kundig</h1>` text inside the link means the name is never invisible to crawlers or screen readers, only the ornament is. That fallback is the whole reason this is safe.
- **User-owned motion switch + reduced-motion handshake** — *Trigger:* user / OS preference. *Mechanism:* a `<input type="checkbox" role="switch" aria-checked>` styled as a 1em dot (`concrete` when off; white with a gold `motion-pulse 2s infinite` ring when on), cloned into both the menu and the footer. It toggles `body.reduced-motion`, which the CSS keys off. If the OS reports `prefers-reduced-motion: reduce` the site does *not* silently degrade — it surfaces `#reduced-motion-notice`: "Reduced Motion Detected — For an optimal site experience, we invite you to enable motion here. [Enable Motion] [No Thanks]". *Reads as:* the preference is honored *and* the user is offered an informed override, rather than being locked out of the design. *Transfers to:* every site whose identity is motion. *Safety:* **production-safe**; this is the pattern most expressive sites are missing. → `motion-toggle-switch`
- **Project carousel** — *Trigger:* drag / arrow / tap. *Mechanism:* Slick.js; `role="tabpanel"` slides, a `role="tablist"` counter rendering as `1 / 8`, `tabindex="-1"` on inactive slide links, arrows with `aria-label="Go to Previous/Next Slide"`. Arrows carry the same `blur(1.5rem) + translateY` exit as the statements. *Reads as:* a portfolio index that doesn't break the cinema. *Safety:* **production-safe** in mechanics (correct roving tabindex, labelled arrows); the jQuery dependency is provenance, not a requirement.

**Reduced motion, precisely.** The automated probe reports `respectsReducedMotion: false` / `prmRules: 0` — that is a **false negative** and the corpus should not repeat it. There is genuinely no `@media (prefers-reduced-motion: reduce)` block in the CSS; instead the preference is read in JS, applied as `body.reduced-motion { … }` (real rules exist: `body.reduced-motion header::before { height: 6rem !important }`, `body.reduced-motion[data-ready][data-main-loading] main { opacity: 0.5 }`), and mirrored into a persistent user control. The outcome for the user is correct — hence `reduced-motion-respected`. The *technique* is worse than the media query for one reason: it does not apply until JS executes. **Do both:** media query for the paint, class for the JS-driven choreography and the user override.

## Production-safety note
- **Scroll toggles a class; CSS transitions the state** — production-safe, and the single most valuable idea here. Cost: none. It replaces most scroll-scrub libraries.
- **Fixed z-ordered media stack** — production-safe as layering; **spectacle-only** as six live videos (7 `<video>` nodes, all Vimeo, `1503` rAF/scroll-pass). Ship posters, decode the active layer only, `pause()` the rest, and drop to a still image on save-data / reduced-motion.
- **`filter: blur(3rem)` on a full-viewport text layer** — spectacle-only. Cost: full-surface raster per frame for the transition window; jank risk on low-end mobile. Safe *only* as a one-shot discrete transition. Never scroll-scrub a blur, never blur a persistent element, and add `will-change: filter` for the transition's duration only.
- **Media dimmed to 0.875 + directional gradient scrim** — production-safe; recommended. Cost: none. Strictly better than a flat scrim for text-over-video contrast.
- **Warm near-black `#181213` instead of `#000`** — production-safe; recommended. Avoids OLED smear and halation, and keeps warm photography from reading cold. Derive every overlay from it (`rgba(24,18,19,α)`), not from black.
- **Accent reserved for system state (focus, alert, media, pulse)** — production-safe. Cost: none. But see the focus caveat below.
- **Fixed footer underlay** — production-safe. Cost: none. Manage the text-over-text collision the site tolerates.
- **Motion switch + reduced-motion notice** — production-safe; **adopt this.** Cost: one checkbox and a body class. The only correction: also ship the `@media (prefers-reduced-motion: reduce)` rules so the page is calm before JS boots.
- **a11y (measured, `craft.a11y` + DOM).** *Good:* a real focus treatment (`button:focus:not(:active) { background: #CC953D }` — a gold fill, plus `:not(:active)` so it doesn't flash on click), `role="switch"`/`aria-checked` on the toggles, `aria-live="polite"` on `<main>`, `aria-controls` pairing every disclosure button to its target, correct roving `tabindex` in the carousel, and `visibility: hidden` on faded overlays so they leave the tab order. *Fail:* the focus style is `:focus`, not `:focus-visible` — a background fill, not an outline, so it is invisible where the button already has one; **45 of 72 interactive targets are sub-44px** (`tap-targets-risky`), including the 1em motion dot and the footer nav. *Partial:* all 21 images carry an `alt` attribute, but nearly all are `alt=""` — correct for the decorative video posters, wrong for the eight project slides, whose titles are only in the adjacent `<h1>` (one slide, "Tofino Beach House", has real alt — the inconsistency gives it away). Hence `alt-coverage-partial`. *Structural:* nine `<h1>` elements (the wordmark plus one per carousel slide) — the statements are `<h2>`, so the document outline is inverted; use one `<h1>`.

## Extracted patterns
- statement-blur-dissolve-stage — full-viewport statements over a fixed, z-ordered media stack; scroll toggles a class, CSS blur-dissolves the outgoing statement and crossfades the layer beneath. The scroll-theater primitive, without a scrub library.
- motion-toggle-switch — a persistent, user-owned motion switch (`role="switch"`) plus a reduced-motion notice that offers an informed opt-in instead of silently degrading. The accessibility contract an expressive site owes its users.
