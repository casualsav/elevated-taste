## What works

- **The page is not a page — it's a single non-scrolling desktop, and the chrome IS the content.** Frames `s00→s10` are pixel-identical except for the media filename in the player's status strip (`BIG-BOAT-ENERGY.mov` → `Cola-Japan-97.avi`): the whole experience fits one viewport, with a menubar pinned top, one application window centred, and a labelled app dock at the bottom. There is no hero, no headline, no scroll narrative — navigation *is* the fiction. The transferable rule: when the product is an environment (a radio, a tool, a world), stop laying out sections and lay out an **environment with affordances**; a user who can drag, close and switch windows is engaged in a way no scroll-jacked hero achieves. The cost is real — no SEO surface, no progressive disclosure, no scroll — so spend this only where the brand *is* the interaction.
- **Depth is built from three zero-blur shadows, not from elevation.** Every button and panel stacks the same triple: `0 0 0 1px #000` (a hard outline), `1px 1px 0 #fff inset` (a top-left light source), `-1px -1px 0 var(--button-shadow) inset` (a bottom-right shade) — and `:active` swaps the last two, so pressing a button physically inverts its bevel. No blur radius, no opacity ramps, no transition. This is a complete, resolution-independent depth system in three declarations, and it costs one paint. Transferable far past retro pastiche: any UI wanting tactile, *legible* affordance at small sizes (toolbars, media controls, dense editor chrome) gets more from a 1px lit/shaded bevel than from a soft `box-shadow` that dissolves at 12px.
- **One soft shadow, used exactly once, to lift the window off the world.** In a system that otherwise forbids blur, the application window alone carries `0 50px 80px -50px rgba(0,0,0,0.3)` — an enormous, low-opacity, negative-spread pool of shade under a hard-edged object. Because nothing else is blurred, that single soft shadow reads unmistakably as *this thing floats above everything else*. Transferable: rationing your only soft shadow to the one element that must float is a stronger z-axis signal than shadowing every card.
- **The palette is a role vocabulary of ~13 custom properties, so the entire OS re-skins from one hue.** `--primary` / `--secondary` (+ `-lighter` / `-darker`) / `--tertiary` / `--backgroundOverwrite` / `--button` + `--button-shadow` + `--button-focus` / `--secondary-button` + `--secondary-button-shadow` + `--secondary-button-focus`. Each interactive hue ships with its own *shade* and *focus* companion (`#F6D5D5` pink → `#7B6B6B` shadow → `#DDC1C0` focus; `#AFE2E5` teal → `#58736F` shadow), and the runtime overrides them on `:root` per session — the captured page runs a pink theme, the stylesheet's static defaults are a different one. The mechanism worth stealing: **don't tokenize colors, tokenize triads** (fill / shade / focus). Bevels stay physically coherent under any theme because the shade is derived from the fill, and theming a whole interface becomes a 13-value swap.
- **Pixel authenticity is enforced globally, not decorated locally.** `* { image-rendering: pixelated; -webkit-font-smoothing: antialiased; }` is a single global rule; type is bitmap faces (Pixolde, ChiKareGo2, Everyday, Ishmeria, "Perfect DOS VGA 437" for the BSOD screen) locked to their native ppem — computed sizes are only `8 / 10 / 16 / 32px`, `letter-spacing: -1px`, no fluid type — and textures are 4×4 base64 PNG tiles stamped at `background-size: 2px 2px` rather than CSS gradients. A period aesthetic survives or dies on *consistency*: one anti-aliased icon, one smooth gradient, one 15px bitmap font scaled off-grid, and the illusion collapses. Transferable to any strong material world (print, terminal, CRT, riso): pick the quantization and apply it at the root, then never exempt anything.
- **The cursor is a first-class design surface, and it carries the feedback that hover animation usually does.** Six role-mapped cursor images — arrow, click, grab (on `.drag-header`), text-insert, loading, resize (on the corner grip) — swap by affordance, while the probe measures **zero hover effects and zero entrance reveals**. The interface tells you what a thing does *before* you touch it, from the pointer, instead of after you touch it, from a transition. Transferable to canvas tools, editors, map UIs and games. Cost, honestly: custom cursors are a desktop-only affordance, don't scale on hi-DPI, and here they're applied via `cursor: … !important` on `*` — which is exactly how you lose the text-selection cursor.
- **Diegetic chrome: every functional control is also a piece of the fiction.** The menubar shows an in-world date and clock (`FRI 10 JUL 1997 · 03:50`), the status strip reports `591×455` like a QuickTime window, the scrollbar is re-skinned with arrow buttons and a dithered track, the "TV" plays black-and-white static with a `.mov` filename, and the ON AIR dot blinks. None of it is chrome-shaped decoration bolted onto a modern layout — the login button, the app switcher and the volume slider *are* the period props. Transferable: in a themed interface, re-skin the real controls rather than adding themed ornaments beside them; a fake window with a real close button beats a real card with a fake title bar.

## Design-system read

- **Type:** Five bitmap/pixel faces used **by role, not by scale** — `Pixolde` (the wordmark and hard titles), `ChiKareGo2` (all UI labels, at 10px), `Everyday` and `Unkown16PixelSer` (body/UI text at 16px), `Ishmeria` (display flourish), `Pixelated Times New Roman` and `Perfect DOS VGA 437` (period props: serif dialog, BSOD screen). The scale is not a ratio, it's a **lattice**: computed sizes are only `8px / 10px / 16px / 32px` with `line-height` in whole pixels (10/15/16/24) and `letter-spacing: -1px` on the small sizes — because bitmap faces only render clean at integer multiples of their native ppem. `fluid_type: false`, one `h1`-less page with 30 `h2`s. Hierarchy therefore comes from **position inside chrome** (title bar > status strip > label) and from face-swapping, never from a size ramp. Only two weights (400, 700).
- **Color:** A candy ground with cream furniture and one ink. Desktop `#F6D5D5` (also `theme-color`) → window/panel cream `#F9F0E9`, lighter `#FCF8F4`, darker `#C8C1BA` → pure white for content wells → black `#000` for every border, glyph and rule. Accents are triads, not swatches: teal `#AFE2E5` (the active/play control) with shade `#58736F` and focus `#9ECEC7`; pink button `#F6D5D5` with shade `#7B6B6B` and focus `#DDC1C0`; buttercup `#FCF4C5` for `::selection` and the scrollbar handle; a single red `#EF4444` for the blinking ON AIR status. Contrast strategy: **everything is separated by a 1px black line, so hue never has to carry legibility** — which is why a pastel palette stays crisp instead of muddy.
- **Spacing rhythm:** Not an 8pt grid — a **pixel grid**. Padding steps are `1 / 2 / 4 / 5 / 6 / 8 / 10 / 17px`, gaps `4 / 6 / 8 / 10px`. Because the bevel is 1px and the borders are 1px, spacing is quantized to the same unit as the ornament; the base unit is effectively 2px, with 4px the working step. Whitespace is *thin* on purpose — the density is what makes it read as an operating system rather than a marketing page.
- **Layout system:** One flex-dominant column (`flex: 405`, `grid: 2`), 100% containers with a `min-h-[771px]` stage. Menubar top / window centred (~600px media well, `456px` container measured) / dock bottom-centre. Radii live in a 2–6px band (`2px×52`, `3px×50`, `4px×64`), with `9999px` reserved for the few true circles. Breakpoints 640/768/1024/1280/1536; at 390px the metaphor *does not degrade into a normal page* — the window goes near-full-bleed, the dock becomes a horizontally scrollable strip flanked by beveled arrow buttons, and the menubar drops the clock. That's the hard part of an OS metaphor, solved: the props shrink, the fiction doesn't.
- **Layering / page architecture:** Effectively **single flat scroll — with no scroll**. The `architecture` probe finds `fixed: 1, sticky: 0, has_static_backdrop: false, has_blend_overlay: false`; the one fixed full-viewport layer is a third-party wallet modal at `z-9999`, invisible (`opacity: 0`, `pointer-events: none`) and not part of the design. No `mix-blend-mode`, no `backdrop-filter` (the one hit is `blur(0px)`). Depth is *drawn*, not composited: the z-stack (`z-20` menubar, `z-10` window furniture, `z-1`/`z-0` desktop) is a window-manager order, and the sense of a raised object comes entirely from the bevel plus that one 50px soft shadow. Worth naming because it inverts the modern default — you can build a convincingly three-dimensional interface with zero glass, zero parallax, and one blurred shadow.
- **Motion / easing intent:** Sparse and *quantized*. Durations `200 / 300 / 1000ms`; easings are stock (`ease`, `cubic-bezier(0.4,0,0.2,1)`) plus one overshooting curve `cubic-bezier(0.23,0.09,0.08,1.13)`. Of 9 `@keyframes`, most are vendor (`vSelectSpinner`, `os-size-observer-*`, `w3m-*`, Tailwind's `ping`); the two site-authored ones are `flashing-dots` (a `visibility` blink) and `dimBackground` (a fade written as **six discrete 20% steps**, 0 → 0.5 alpha). Motion communicates *machine*, not *silk*: state changes are instantaneous (the button bevel has no transition at all) and the one fade is stepped like a dither dissolve. The continuous work — 22 mousemove listeners, 162 rAF calls — is dragging, resizing, and the static TV, not decoration.
- **Density:** High and deliberate: 88 buttons, 131 interactive elements, 125 images inside one viewport. It stays legible because every element is boxed in a 1px black border on a cream fill, so the eye parses *regions* before it parses content — the same reason a 1997 GUI could show fifty controls without noise.
- **Hierarchy:** **Position + framing.** The dominant device is enclosure (what is inside which box), then face-swap, then the single teal fill on the primary control. Scale contributes almost nothing — the biggest type on the page is 32px.
- **Restraint:** No gradients. No blur except one shadow. No rounded cards. No scroll. No entrance animation, no hover transition, no parallax, no cursor-follower, no IntersectionObserver at all. No display type. The entire expressive budget is spent on *materials* (bitmap fonts, dither tiles, pixel cursors, pixel icons) and on *interactivity* (drag, resize, play).

## Interaction & motion

The evidence is unusually clear about what this site does **not** do: `usesIntersectionObserver: false`, `entranceReveals: 0`, `hoverEffects: 0`, `cursorFollowers: 0`, `libraries: []`, `prmRules: 0`. The three "scroll effects" the probe diffed all belong to the hidden vendor wallet modal (`w3m-modal` pinning; a Tailwind `ping` span's opacity/scale) — the page itself does not scroll, and frames `s00→s10` confirm it. All real motion is **pointer-driven**.

- **Drag-and-resize window chrome** — *Trigger:* drag. *Mechanism:* pointer-delta on a title-bar handle (`.drag-header`, grab cursor) translates a positioned window; a bottom-right corner grip (`.handle-br`, resize cursor) drives width/height. 22 mousemove listeners + 162 rAF calls are the tell. *Reads as:* direct manipulation — the single interaction that makes the OS metaphor true rather than decorative. *Transfers to:* editors, canvas tools, dashboards with floating inspectors, anything with a "workspace." *Safety:* **production-safe** if you commit to the accessibility work — animate `transform` (never `top`/`left`), give the handle a `role`/`tabindex` and arrow-key nudging, and fall back to full-bleed on touch (as this site does). Resizing by grip *does* reflow — throttle to rAF and let go of `will-change` when idle. See `patterns/draggable-desktop-window.md`.
- **Bevel-inversion press** — *Trigger:* active/press. *Mechanism:* the inset highlight and inset shade swap corners on `:active` (`1px 1px 0 #fff inset, -1px -1px 0 var(--button-shadow) inset` → reversed), with **no transition** and no geometry change. *Reads as:* a physical key going down; the absence of easing is what makes it feel mechanical rather than gooey. *Transfers to:* any tactile control surface. *Safety:* **production-safe** — one composited paint, no layout, nothing to disable under reduced-motion. See `patterns/beveled-chrome-panel.md`.
- **Focus by fill, not by ring** — *Trigger:* focus. *Mechanism:* `button:focus { outline: none }` and the focus outline color is transparent; instead the control repaints its fill to the theme's `--*-focus` companion (`#DDC1C0` / `#9ECEC7`). *Reads as:* period-correct keyboard focus. *Transfers to:* themed interfaces that can't afford a modern focus ring. *Safety:* **production-safe only if the fill change clears 3:1 against the resting fill** — here it barely does. Prefer keeping a real `:focus-visible` outline and adding the fill change on top.
- **Stepped alpha dissolve** (`dimBackground`) — *Trigger:* load / state change. *Mechanism:* a modal scrim fades `rgba(0,0,0,0) → 0.5` in six explicit 20% keyframe stops rather than two. *Reads as:* a dithered, frame-by-frame dissolve — the motion is quantized to match the pixels. *Transfers to:* any world with a coarse material (pixel, print, CRT); a `steps()` timing function achieves the same thing with two keyframes. *Safety:* **production-safe**; must be skipped under reduced-motion (it isn't here).
- **Visibility blink as status** (`flashing-dots`) — *Trigger:* load, infinite. *Mechanism:* `@keyframes { 100% { visibility: hidden } }` toggling the red ON AIR dot and the loading ellipsis. Toggling `visibility` (not `opacity`) is what gives the hard on/off blink of an LED with zero intermediate frames. *Reads as:* live broadcast. *Transfers to:* live/recording indicators. *Safety:* **spectacle-only as written** — an infinite blink is a vestibular and attention hazard, must freeze under `prefers-reduced-motion`, and must never be the *sole* carrier of the "live" state (pair it with the word ON AIR, as this site does).
- **Affordance-mapped custom cursors** — *Trigger:* hover. *Mechanism:* per-role `cursor: url(pointer|click|grab|insert|loading|resize.svg) <hotspot>`, class-switched by context. *Reads as:* the pointer is part of the world. *Transfers to:* games, canvas editors, brand experiences. *Safety:* **spectacle-only** — desktop-only, no hi-DPI scaling, and the `* { cursor: … !important }` application here overrides the browser's text-selection and disabled cursors. If you do it, scope it to the elements that need it and never to `*`.

**Reduced motion is not respected** (`prmRules: 0`, `respectsReducedMotion: false`). With an infinite blink and an animated static field on screen, that is the site's clearest a11y liability.

## Production-safety note

- **OS-metaphor page architecture** — **spectacle-only.** Cost: no scroll, no document outline (0 `main`/`nav`/`footer` landmarks, 0 `h1`), SPA-rendered DOM (the captured HTML is an empty `<body>` + modal — nothing for a crawler or a reader-mode to see), and a mobile fallback you must design separately. Ship it for a brand world, never for a docs site or a checkout.
- **Bevel depth system, tokenized color triads, pixel lattice type, dither-tile textures** — **production-safe** and highly portable. Zero perf cost; the bevel is cheaper than a soft shadow.
- **Custom cursors, infinite blink, continuous static field** — **spectacle-only.** Costs: main-thread rAF and battery for the noise; motion hazard for the blink; broken pointer semantics for the `!important` cursor.
- **a11y (measured, `craft.a11y`) — mixed.** `focus_visible: true` but carried by a fill swap after `outline: none` (fragile); `img_alt_ratio: 0.42` — over half of 125 images unlabelled, and in an icon-driven dock that's the *entire* navigation; `small_tap_targets: 15` of 131 interactive elements; `reduced_motion: false`. Fixes, in order: alt text on every dock icon, a real `:focus-visible` outline, a `prefers-reduced-motion` block that stops the blink and freezes the static, 44px hit areas on the media transport.

## Extracted patterns

- beveled-chrome-panel — a 1-bit depth system: hard 1px outline + inset light/shade corners that invert on press, with fill/shade/focus color triads and a 2px dither-tile texture; for tactile toolbars, media transports and any retro or high-density control surface.
- draggable-desktop-window — a keyboard-accessible, transform-driven floating window with a drag title bar, close/zoom controls, a status strip and a corner resize grip; for OS-metaphor brand sites, canvas tools and workspace UIs.
