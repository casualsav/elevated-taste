## What works (transferable principles)

- **A serif-display / sans-body pairing, where the serif↔sans contrast IS the personality.** The site runs two families: a custom *display serif* (`LocomotiveNew`) for headlines at ~110px, and a *grotesque sans* (`HelveticaNowDisplay`) for all body, nav, labels, lists and footer at ~15px — a ~7× scale ratio, and notably in essentially one 400 weight that spans **both** families. Mechanism: the modulated serif blown up to poster size reads literary and authored at the top of the hierarchy, while the neutral grotesque keeps the running text crisp and un-decorated below it — the *juxtaposition* of the two does the work, so no bold and no color are needed to rank. (The raw `"Times New Roman"` count-2 entry is a generic fallback-stack remnant, not a rendered face.) Transfers to any editorial/agency/portfolio voice that wants to feel un-SaaS: let one expressive serif own the display tier and a quiet sans carry everything else — and keep the body sans at generous leading since it sits at ~15px (see the long mobile intro paragraph).

- **List-as-gallery: project names ARE the portfolio.** "Featured work" is not a thumbnail grid — it is a stack of full-width serif rows (Scout Motors / Populous / Mate Libre / Destigmatize), each a horizontal rule-separated band that presumably swaps a hover image. Mechanism: turning the index into giant readable type makes the *names* the hero and lets one column carry the whole catalogue; whitespace + rules give rhythm without boxes. Transfers to portfolio indexes, case-study menus, changelog/article lists — anywhere a card grid would feel busy. The "Articles / Culture / Store" block below reuses the exact rule-row system at small scale, proving it scales both ways.

- **One loud full-bleed hero, then a calm white document.** The page opens on an edge-to-edge red-lit portrait (a single arresting image), then immediately drops to a quiet black-on-white editorial layout for everything else. Mechanism: spending all the spectacle budget in the first viewport buys attention, then withdrawing it makes the content legible and fast — contrast of intensity, not constant intensity. Transfers to any landing page: front-load the one cinematic moment, keep the body sober.

- **Tiny boxed labels as a quiet metadata language.** Recurring `[OPS]` / `[DES]` / `[UNIT]` micro-tags in hairline-bordered boxes annotate sections in ~11px caps. Mechanism: a consistent boxed-label motif gives editorial chrome a system — it reads as "spec sheet / studio" without shouting, and separates labels from content typographically. Reusable as section eyebrows, version chips, or category tags in docs and dashboards.

- **The footer is a typographic illustration.** The address block renders the studio's coordinates as a line of mixed serif text and custom glyphs/dingbats (arrows, clovers, a clock, framed digits) — "1211 Jean-Talon Est, Montréal, Canada H2R 1W1 · info@locomotive.ca" set as a near-decorative composition. Mechanism: encoding mundane contact data as a glyph collage turns the dead zone of a footer into a brand signature while still being real, copyable information. Spectacle-only as drawn, but the *principle* — treat the footer as a designed object, not a list — transfers anywhere.

- **Accent color is a single electric blue, held in reserve.** The system is black/white/red-hero; one vivid blue (`#312dfb`) appears only as an interaction color (link/cursor/hover), surfacing in the raw as exactly one background instance. Mechanism: reserving a saturated hue *exclusively* for interactivity makes every blue thing legibly "actionable" and keeps the resting page monochrome. Transfers directly to product UI — pick one accent, spend it only on action.

## Design-system read

- **Type:** A **two-family pairing** (raw `type_detail.families`): a custom *display serif* (`LocomotiveNew`) for headlines, and a *grotesque sans* (`HelveticaNowDisplay`) for all body / nav / labels / lists / footer. The serif owns the big sizes, the sans owns the running text. Scale is two-tier: ~110px (lh 110px) display **serif** / ~70px (lh 77px) secondary headings / ~26px (lh 31px) sub / ~15px (lh 19.5px) body **sans**. One weight (400) throughout — and that 400 spans *both* families. Hierarchy = **scale contrast + the serif↔sans contrast**, not weight. (The raw `"Times New Roman"` is a generic fallback-stack remnant, not the rendered face.) **Tracking:** raw `type_detail.tracking_by_size` is empty and the H1 reports `tracking: normal` — so this site does **not** tighten display type; spacing stays at each family's native default at every size (frame-estimated, tracking not measured per-size). That is itself a choice: the display serif's letterforms are already tight, so blowing them to 110px needs no negative tracking the way a grotesque would.
- **Color:** Light-mode editorial. `bg` pure white `#ffffff`; `fg` near-black; the hero is full-bleed red (`#d11b10` lightening over a dark portrait, deep shadow `#200d12`). `accent` is one electric blue `#312dfb`, reserved for interaction (white text used over the red/black imagery). No surface fills, no semantic palette — red is image, blue is action, everything else is ink on paper.
- **Spacing rhythm:** Section padding in big steps (raw shows 60/80/150px block padding) against tight control padding (7px). The rhythm is large vertical voids between full-width rule rows; horizontal rules (not gaps) do the dividing. Gutter/gap ~20px in the few grid zones (store, footer columns).
- **Layout system:** Full-bleed hero, then a wide single content measure with a 2-column "label | content" split (left margin label, right content) for the Articles/Culture/Store lists and the about block. Store is a sparse 2-up product grid. Footer is a 3-column link matrix above the glyph address line. Mobile collapses everything to one column and stacks the label above its content; the serif display reflows to multi-line — no layout reinvention.
- **Layering / page architecture:** The hero is a **fixed backdrop, not a scrolling band** — the one structural move the parallax framing below understates. `architecture.layers` puts `div.c-home-hero_background` at `position:fixed`, `z-index:-1`, 100vw×100vh (role `static-backdrop`), and **every** section stacked above it is transparent (`surfaces.summary.transparent_height_pct: 100` — all 5 blocks `rgba(0,0,0,0)`). So the red-lit portrait stays pinned to the viewport while the white editorial document — transparent itself, colored only by the page's opaque white base — rises and buries it: **s00** full portrait → **s01** white paper climbing over its lower edge with the face still framed where it began → **s03** pure white, portrait gone. Above the document the fixed nav caps the z-order — `c-header` at z-800 (`mix-blend-mode:difference`) over its plate `c-header_bg` at z-740 (opacity 0→1), with a `c-video-modal` overlay reserved at z-1000. Depth here is **one pinned backdrop revealed through a transparent document that then covers it** — not stacked parallax planes.
- **Motion / easing intent:** Real `.motion.params`: durations cluster at **200 / 150 / 250 / 300ms** (short, crisp) on easings `cubic-bezier(0.215,0.61,0.355,1)` (easeOutCubic) and `cubic-bezier(0.23,1,0.32,1)` (expo-out) — plus a bare `ease` default where Locomotive Scroll drives per-frame. Fast, decelerating micro-interactions (link hovers, boxed labels, list-row image swaps) read as crisp craft rather than slow spectacle. But the page's actual signature is **scroll-orchestrated**: a fixed nav that recolors white→blue→black as the red hero parallaxes out from under it, all riding **Locomotive Scroll smooth-scroll inertia** (the studio authors the library — `data-scroll`, 778 rAF / 1 scroll listener in one pass). Full choreography, evidence, and per-technique safety in **Interaction & motion** below.
- **Density:** Reads airy, is actually a full agency site (work index, 13 extras, articles, culture archive, store, full contact). Kept legible by rule-separated rows, tiny margin labels, and one idea per band.
- **Hierarchy:** Dominant device is **scale** (giant serif names) reinforced by **position** (label left / content right) and **rules** as the separator. Weight and color are almost never used to rank.
- **Restraint:** No card fills, no shadows, no rounded corners, no gradients (the only gradient is a `rgba(255,255,255,0)→#fff` fade-to-white edge mask, not decorative), no second display weight, no accent beyond the one blue. Expressiveness is bought with *the serif at scale, one cinematic image, glyph craft, and smooth-scroll inertia* — not with stacked effects.

### Components (from `.craft.states`)
- **Nav / link:** resting state is plain text (white over the red hero, then ink-black over the white doc); **focus** draws a `1px solid rgb(16,16,16)` outline (focus-visible confirmed across `Locomotive®`, `Read more about this pro…`, `See all projects`, project links — real, consistent focus rings). **Hover** is the reserved electric blue `#312dfb` (link/cursor accent; not separately captured as a state delta but it is the one interaction color). No button-chrome component — the site has no filled buttons; "Let's talk" / "Buy now →" are text links with an arrow glyph.
- **Card:** there are no cards (radius 0, shadow none). The closest analog — the work-index row and the store product cell — has **no resting fill or border**; structure comes from the horizontal rule above/below and, on the work rows, an (un-captured) hover image swap. No hover-lift, no elevation delta.
- **Input:** none on the home page (contact is an external "Let's talk" link); no input states captured.
- **Disabled:** none captured (`states.disabled: []`) — no disabled affordances exist on this page.

### Grid / container
12-column grid present in the raw layout probe (`grid.columns: [1, 12, 2, 4]` — the `1`/`2`/`4` are span values inside a 12-track frame; the wide single content measure plus the `label | content` 2-up and the 2-up store grid all resolve onto it). ## Interaction & motion

Locomotive's motion is **restrained-but-signature**, and it is the rare expressive site that **respects `prefers-reduced-motion`** (`prmRules: 5`, `respectsReducedMotion: true`, `craft.a11y.reduced_motion: true`) — unlike teak, reduced-motion users get a sane fallback. The capture is genuinely light: **6 scroll effects** (after dropping `from==to` noise), **2 IntersectionObservers over 7 targets**, **778 `requestAnimationFrame` calls** in one scroll pass, **1 scroll listener**, **2 mousemove**, **0** captured entrance/hover/cursor catalogs. Library is **Locomotive Scroll** (`data-scroll`, the studio's own smooth-scroll engine — the 778 rAF + single scroll listener is its inertia loop). 10 `@keyframes` exist but most belong to a **disclaimer/age-gate Easter egg**, not the main scroll (names: `preloaderAppear`, `swiper-preloader-spin`, `spin`, `shake`, `fall`, `featuredProjectsAllFlash`, `lisaDisclaimerFlash`, `lisaDisclaimerProcedure`, `lisaLoader`, `lisaCursor`). Stack: **Locomotive Scroll** · IntersectionObserver · CSS `@keyframes` (preloader/overlay only). Frames cited: `corpus/expressive/screenshots/locomotive-ca/frames/`.

- **Smooth-scroll inertia (momentum scroll)** — *Trigger:* scroll-progress (continuous). *Mechanism:* native scroll is intercepted; content position is lerped toward the target each rAF tick, so the page glides/decelerates instead of snapping (`data-scroll`, 778 rAF + 1 scroll listener; the engine the studio literally ships). *Reads as:* the whole document feels weighted and physical — the defining "Locomotive" feel. *Transfers to:* agency / portfolio / brand-experience sites that want a tactile scroll; never a task app or docs. *Safety:* **spectacle-only** — hijacks the scrollbar, find-in-page, keyboard paging, and trackpad expectations; main-thread lerp is a jank risk on low-end devices. The honest mitigation, which this site actually ships, is a `prefers-reduced-motion` path back to native scroll. → no expressive recipe yet (see `patterns_to_build`).
- **Fixed nav that recolors as the hero passes** — *Trigger:* scroll-progress + in-view (captured `text color-shift rgb(255,255,255)→rgb(0,0,0)` on the `Locomotive® Work Agency Careers Store…` bar, plus `position: pin (fixed)` on the same node). *Mechanism:* the nav holds `position: fixed`; its text color is driven from white→(electric-blue mid)→black as the red full-bleed hero scrolls out from under it onto the white document. *Reads as:* one persistent frame whose chrome adapts to whatever's behind it — seen directly s00 (white nav on red) → s01 (blue nav as the hero edge lifts) → s03 (black nav on white). *Transfers to:* any site with a dark/photographic hero above a light body that needs a single always-readable nav. *Safety:* **production-safe** (native `position:fixed` + a color transition; pair the blue mid-state with a non-color cue and ensure contrast holds against both backgrounds). → `scroll-linked-recolor` (production recipe).
- **Full-bleed hero parallax** — *Trigger:* scroll-progress / in-view (captured `transform` / `transform/parallax` on `div.c-home-hero_background`). *Mechanism:* the red-lit portrait background translates at a different rate than the masthead lockup over it, so the image drifts up behind the type as you scroll off the first viewport. *Reads as:* depth on the one cinematic moment — the portrait recedes while `[OPS][DES][DEV] Locomotive Digital-first Design Agency` peels up over its lower edge (s00→s01). *Transfers to:* a single hero image you want to feel dimensional, not pasted-on; one layer only. *Safety:* **production-safe if the drift is small** (compositor `transform`); becomes spectacle if stacked into many planes. Cap to one background layer + a subtle rate. → `parallax-drift` (production recipe).
- **Header backdrop fade-in** — *Trigger:* in-view (captured `opacity 0→1` on `div.c-header_bg`). *Mechanism:* a header background panel fades from transparent to opaque once, so the fixed nav gains a legible backing as soon as you leave the hero. *Reads as:* the nav "lands on paper" when the photo is gone — a one-shot polish beat, not a loop. *Transfers to:* any transparent-over-hero nav that needs a solid plate once scrolled. *Safety:* **production-safe** (single opacity transition, GPU-cheap, fires once). → `scroll-reveal-in-view` (production recipe; opacity-only variant).
- **Disclaimer / age-gate Easter egg (custom cursor + loader)** — *Trigger:* load + pin (the `🔞`/`🍺` masthead and the `Close` node captured as `position: pin (fixed)`; keyframes `lisaDisclaimerFlash` / `lisaDisclaimerProcedure` / `lisaLoader` / `lisaCursor` / `shake` / `fall` / `preloaderAppear`). *Mechanism:* a fixed overlay with its own animated custom cursor and loader procedure — a brand Easter egg, not part of the document scroll. *Reads as:* studio personality / craft signature; a self-contained moment. *Transfers to:* brand-experience interstitials only — an intentional, dismissible overlay. *Safety:* **spectacle-only** — custom cursors and shake/fall keyframes are exactly the flourish to gate behind reduced-motion (this site's `prmRules` cover it) and make trivially dismissible (`Close` is pinned and reachable). No recipe; reuse the *principle* — fence the spectacle into an opt-in overlay, keep the main document calm.

A note on what is **static**: the `serif-list-index` rows (s03), the `Extras (13)` / Articles / Culture / Store blocks (s06), and the footer glyph composition (s09) show **no captured scroll transform** of their own — they ride the global smooth-scroll inertia but do not parallax, scale, or reveal individually. The hover image-swap on work rows is plausible but was **not captured** (0 hover entries) — do not assume it.

## Production-safety note

- **Book-serif (Times) at display scale** — **production-safe.** It is a system font, so zero load cost and instant render. Caveats: at ~15px a tight serif body can hurt readability — keep body leading generous (here lh ≈ 1.3) and consider ≥16px; Times specifically reads as a strong editorial choice, not a neutral default.
- **List-as-gallery (rule-row index)** — **production-safe** and an excellent pattern. Trivially responsive (one column), accessible (real headings/links in order), cheap. Only ensure the hover-image swap has a non-hover fallback (touch/keyboard) and that rows are real links with visible focus.
- **Full-bleed cinematic hero** — **production-safe** with discipline. Cost is LCP/bandwidth of a large hero image; serve responsive sizes, lazy-load below the fold, and provide alt text. The "spend spectacle once" structure is itself the safe part.
- **Boxed micro-labels (`[OPS]`/`[DES]`/`[UNIT]`)** — **production-safe.** Pure CSS border + caps; just keep ~11px caps above contrast minimums and don't encode meaning in the bracket alone (give the section a real heading too).
- **Reserved single-accent interaction color** — **production-safe** and recommended. The only risk is using color as the *sole* affordance signal — pair the blue with underline/focus styles for a11y.
- **Glyph-encoded footer (dingbat address composition)** — **spectacle-only.** Gorgeous, but a footer where digits/arrows are decorative glyphs risks screen-reader gibberish, copy-paste breakage, and contrast traps. Safe version: render real, semantic text and reserve the glyphs as `aria-hidden` ornament around it; never let a clover *be* the comma.
- **Smooth-scroll inertia (Locomotive Scroll)** — **spectacle-only / use with care.** Hijacking native scroll can break scrollbars, find-in-page, keyboard paging, and `prefers-reduced-motion`; on an agency showcase it's signature, in a task app it's a liability. Always provide a reduced-motion path back to native scroll.

- **A11y scorecard (honest, from `.craft.a11y`).** *Wins:* `img_alt_ratio: 1.0` — **every one of the 6 images has alt text** (perfect); `focus_visible: true` with real `1px rgb(16,16,16)` outlines confirmed on nav and project links; and — unusual for an expressive/spectacle site — **`prefers-reduced-motion` IS respected** (`reduced_motion: true`, `prmRules: 5`), so the Locomotive-Scroll inertia and the disclaimer cursor have a fallback. *Defect:* **35 of 61 interactive elements are small tap targets** — the tiny boxed micro-labels, dense top nav, and footer glyph line fall under the 44px touch minimum; on mobile, pad these or enlarge the hit area. Net: this is a rare expressive exemplar that mostly passes a11y; the one thing to fix when transferring is tap-target size.

## Extracted patterns

- **serif-list-index** — a portfolio/section index rendered as full-width, rule-separated serif rows at display scale instead of a thumbnail grid (project names are the gallery; optional hover-image swap). Reuse for portfolio indexes, case-study menus, article/changelog lists. *production-safe.*
- **glyph-encoded-footer** — a footer address/contact block composed as a typographic illustration mixing real text with custom dingbat glyphs (arrows, framed digits, marks). Reuse to turn a footer into a brand signature. *spectacle-only* (keep semantic text underneath the ornament).
- **fixed-backdrop-reveal** — (reused, canonical home `corpus/production/patterns/`) the hero-scoped variant: the full-viewport red portrait pinned at `position:fixed`, `z-index:-1` is revealed through the first viewport, then buried as the transparent document (colored only by its opaque white base) rises over it (frames s00→s03) — the layer holds still, the paper moves. Distinct from `parallax-drift`, which translates the layer instead. *production-safe.*

**Motion recipes reused (canonical homes in `corpus/production/patterns/`, cited cross-corpus):** `scroll-linked-recolor` (the white→blue→black fixed-nav recolor), `parallax-drift` (single-layer hero parallax), `scroll-reveal-in-view` (header-backdrop opacity fade).

**patterns_to_build:**
- **smooth-scroll-inertia** — momentum/lerped scroll (the defining Locomotive Scroll behavior): native scroll intercepted, content position eased toward target per rAF, with a **mandatory** `prefers-reduced-motion` → native-scroll fallback and a resting DOM. No corpus recipe exists yet (the production motion set has no momentum-scroll pattern); this is the genuinely-new, spectacle-only technique here and worth authoring as the first expressive motion recipe.
