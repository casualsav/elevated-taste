## What works (transferable principles)

- **When density is the product, put the whole taxonomy on one page and let the eye scan, not the cursor click.** The homepage renders ~1,300 leaf categories across 27 top-level sections in a single ~7,800px scroll — no carousels, no "shop by department" landing, no progressive disclosure. Every destination in a 700,000-SKU catalog is one click away because it is already on screen. Transfers to any surface whose user arrives knowing what they want (parts catalogs, admin consoles, docs indexes, icon pickers): *disclosure costs more than density* when the visitor's task is retrieval, not discovery. The corollary — this is exactly wrong for a browse-to-be-inspired surface.

- **At extreme density, hierarchy comes from rules and hue, not from scale.** The full type range is 10.5px (item labels) → 19px (section headings): a **1.8× total spread**, where a typical marketing page runs 4–6×. Sections are separated instead by a **1px green rule above each `h1`** plus a hue flip (green heading vs. charcoal subheading vs. grey label). Transfers to any information-dense screen where you cannot afford the vertical space that scale-based hierarchy consumes: buy separation with a hairline and a color, and spend zero pixels of height.

- **Quantize the catalog to one fixed cell and every group tiles for free.** Each item is a rigid `72 × 114px` cell — a 60px icon, 5px gap, two clipped lines of label — and each subcategory's list is given a width that is a literal multiple of that cell (`3 → 216px`, `11 → 792px`, `22 → 1584px`). Because widths are cell-quantized, adjacent subcategories float into the same row with no grid engine, no fractional columns, and no reflow surprises: the layout is arithmetic. Transfers to icon grids, sprite pickers, product tiles, media libraries — pick a cell, publish it as a token, size containers in multiples of it. → `fixed-cell-catalog-grid`

- **Ship one sprite per group instead of one image per item.** Every subcategory's icons live in a single horizontal PNG strip; the cell just offsets `background-position` by `-60px × n`. ~1,300 icons cost 36 image requests. Even in an HTTP/2 world the principle holds in its modern form — one SVG sprite + `<use href="#id">` per group — because you also get one cacheable, versioned asset per editorial unit rather than a thousand independently-invalidating ones. Transfers to any grid of many small, uniformly-sized graphics.

- **Uniform, silhouette-only illustration turns a wall of icons into a scannable index.** All ~1,300 icons are the same grey line-art rendering at the same optical weight in the same 60px box — no color, no perspective, no brand shine. Difference between cells therefore carries only *shape*, which is the one signal the user needs to spot a hex nut versus a shoulder screw. Transfers to any large icon system: normalize weight, size, and palette so the drawing communicates identity and nothing else. (Contrast with `saturated-icon-tile-grid`, where color is the differentiator because the count is small.)

- **Ration the accent to exactly one structural hue, and let a second hue exist only as a 2px stripe.** Green `#336633` does all the load-bearing work — section rules, headings, primary buttons, the service-block top borders. The brand yellow `#fed700` appears *only* as a 2px border under the masthead. Blue `#006699` is reserved for secondary/utility links so "clickable elsewhere" never competes with "structure." Transfers anywhere: give each hue exactly one job, and give the loudest hue the smallest surface area.

- **Chrome is a hairline, never a card.** Tiles are a white box with a `1px #eee` border; radius appears 9 times on the whole page (2px on buttons, 4px on two panels); the four box-shadows are all ≤7px blur and belong to floating overlays. Nothing is elevated that does not actually float. Transfers to dense UI: reserve shadow for the z-axis (popovers, drawers, dialogs) and draw every in-flow boundary with a 1px line — a page of 1,300 shadowed cards is unreadable mush.

- **Spend motion only on disclosure.** Zero `@keyframes`, zero IntersectionObservers, zero scroll listeners, zero `requestAnimationFrame` in a full scroll pass. All 27 transition rules animate chrome that is *opening or resizing*: the catalog drawer's `left`, the scrim's `opacity`, the masthead's `height`, the autocomplete panel's `height`. Nothing decorative moves. Transfers to any tool people use daily: motion that narrates a state change is respected; motion that narrates your taste is a tax paid on every visit.

## Design-system read

- **Type:** One family, effectively. Arial/Helvetica for body and item labels, with Helvetica Neue eText (Roman/Medium) as the licensed upgrade layer and two display faces held in tiny reserve — `FuturaLTPro-BoldCond` for the uppercase masthead words and `DINNextLTPro-Medium` for buttons. Scale is a flat UI ramp: **10.5 / 11 / 12 / 13 / 16 / 18 / 19px** — 2,402 of 2,504 text nodes are weight 400; only 102 are 700. Leading is unusually tight and *inverted* against convention: 1.15 on the 10.5px labels (12.075px) so a two-line part name fits one clipped cell, versus 1.3 on 12px body. Tracking is used once, at exactly one size: `-0.5px` on the 19px headings. Hierarchy is created by **color + rule**, with scale and weight as minor reinforcement.
- **Color:** A grey ramp doing everything and one hue doing structure. `bg #ffffff` → `fg #333333` (charcoal) → `label #666666` → `subtle #999999` → `border #eeeeee` / `#cbcbcb`. The accent is a single desaturated forest green `#336633` (hover `#3c773c`, active `#2b552b`, tile wash `#edf2ed`), used for section rules, headings, and the primary button. `#006699` is the utility-link blue; `#fed700` is a 2px brand stripe under the masthead and the top edge of the login popover; `#ffffb5` is the autocomplete row hover. Not a single gradient exists except a 1px-tall one faking a rule.
- **Spacing rhythm:** There is no 8px grid — the rhythm is the **cell**. Horizontal padding is `5px` on 692 elements (the cell's internal gutter); the vertical unit is the 60px icon + 5px + two label lines, clipped at 114px. Above cell scale, the scaffolding uses 10 / 12 / 20 / 22 / 24 / 48px. Whitespace does almost no separating work — rules do.
- **Layout system:** An **app shell, not a document**. `html, body { height: 100%; overflow: hidden }`; the masthead is `position: absolute` at `top: 0` and `#MainContent` is the single `overflow: auto` scroll container. Inside it, a flex row: a `flex: 0 0 195px` sticky nav rail and a `flex-grow: 1` category column padded 20px. Zero CSS Grid on the page (40 flex containers, 0 grids) — the dense area is pure float packing over cell-quantized `ul` widths. **No responsive design at all:** `<meta viewport content="width=1024">`, zero media queries, zero breakpoints, and the mobile capture is pixel-identical to desktop (the same 33 nav links, the same 19px `h1`). That is a deliberate, defensible bet for a desktop procurement tool used at a workbench — and it is the one thing here you should not copy without the same bet.
- **Layering / page architecture:** Single flat scroll inside a fixed shell; no static backdrop, no blend overlay, no `backdrop-filter` anywhere (`blend_glass` is empty on all three axes). The z-axis appears only on demand: a `position: fixed` 400px catalog drawer at `z-index: 10000005` above a `position: fixed`, `inset: 0`, `pointer-events: none`, `opacity: 0` grey scrim at `10000000` — both resting invisible and inert. Two `position: sticky` elements do the wayfinding: the 195px nav rail (`top: 0`, `max-height: calc(100vh - 110px)`, `overflow-y: auto`) and, nested inside it, its own 16px title bar that pins to the rail's top as the rail's internal list scrolls. The `transparent_height_pct: 90` in the profile is the ordinary "sections have no background" case, not a reveal effect — there is nothing behind them.
- **Motion / easing intent:** Durations `100 / 150 / 200 / 300 / 500ms`; easings `ease` and `ease-out` only — no custom cubic-béziers, no spring. **0 keyframes, 0 animation rules, 27 transition rules.** Every one of them animates a *disclosure or resize*: drawer `left: -400px → 0` (300ms ease-out), scrim `opacity` (300ms ease-out), masthead `height` (300ms), login popover `visibility, opacity` (150ms ease-out), autocomplete `height` (200ms linear). Motion means "something changed," never "look at this."
- **Density:** Among the highest in the corpus: ~2,500 text nodes, 739 interactive elements, 1,292 of them set at 10.5px, on one page. It stays legible because the *unit* is legible — a constant cell, a constant icon weight, a constant label position — so the eye parses shape-and-position rather than reading. Density is survivable when the grid is boring.
- **Hierarchy:** **Color and rule**, in that order — green heading over a green hairline, charcoal bold subheading, grey label. Position (the sticky rail's order) is the secondary device. Scale is nearly inert; weight is used once per level.
- **Restraint:** No hero. No headline. No gradient. No card shadow. No hover lift. No scroll reveal. No illustration style. No dark mode. No mobile layout. The page's entire visual budget was spent on 1,300 correctly-drawn icons, and it shows.
- **Components (captured states):**
  - **Catalog cell:** rest — white box, `1px #eee` border, 60px sprite-offset icon, centered 10.5px `#666` label at 1.15 leading, `overflow: hidden` clipping past two lines. Hover — a pale green wash `#edf2ed` (token `--color-hovertilegreen`); **no lift, no shadow, no scale**.
  - **Primary button:** `#336633` fill, white 12px DIN Medium, uppercase, `2px` radius, `1px` same-green border, `transition: background-color 0.3s` → hover `#3c773c`, active `#2b552b`. Color-only state change.
  - **Search field:** 32px tall, `1px #999` border, 2px radius; on focus the border *does not change* (`:focus { border: 1px solid #999 }`) and `outline: none` is set across the whole search container — a real defect, listed below.
  - **Autocomplete row:** hover fills pale yellow `#ffffb5` — the one place the brand yellow becomes a surface rather than a stripe.
  - **Nav rail link:** 10.5px, `4px solid white` left border reserved as the active-marker channel, `text-indent: -12px` with `padding-left: 12px` so wrapped lines hang correctly.
- **A11y (honest, incl. defects):** **No `prefers-reduced-motion` block** (0 PRM rules) — low harm here, since the only motion is a 300ms drawer, but the drawer slide will still play. **No authored `:focus-visible`** — interactives fall back to the UA outline, and `.container-searchentry *, :focus, :hover { outline: none }` explicitly *removes* it from the primary search control, which is the page's most important widget. **`img_alt_ratio` 0.78** across 36 images — and note the ~1,300 catalog icons are CSS `background-image` sprites, i.e. invisible to assistive tech by construction; their accessible name comes entirely from the anchor's text label, which is the right call, but it means the visual index has no non-visual equivalent. **69 of 739 interactives are below 44px** — the 72px cell is fine, but the 10.5px rail links and 11px footer links are not. **10.5px `#666` on white** is ~5.7:1 — it passes contrast and still fails legibility for many users; there is no text-size control.

## Interaction & motion

This page is, by measurement, **static**: `keyframeCount: 0`, `cssAnimationRules: 0`, `usesIntersectionObserver: false`, `scrollListeners: 0`, `mousemoveListeners: 0`, `rafCalls: 0`, `libraries: []`, `entranceReveals: 0`, `carousels: 0`, `canvas: 0`, `video: 0`. Nothing reveals, parallaxes, pins-and-plays, or follows the cursor. The frame sequence shows content flowing past two unchanging elements — the absolute-positioned masthead and the sticky rail — and nothing else. The 27 transition rules are the entire motion system, and they exist to explain state changes. Stack: plain CSS transitions, `position: sticky`, `position: fixed`. Reduced motion is **not** declared.

- **Off-canvas drawer with an inert scrim** — *Trigger:* tap/click (catalog button). *Mechanism:* a fixed 400px panel transitions `left: -400px → 0` over 300ms ease-out while a fixed, `inset: 0` grey layer transitions `opacity: 0 → ~0.5`; the scrim rests at `pointer-events: none` so it costs nothing and blocks nothing until opened. *Reads as:* a second surface sliding over the page, with the page visibly demoted rather than replaced. *Transfers to:* any nav drawer, filter panel, or cart flyout. *Safety:* **production-safe** — but the reference recipe below animates `transform: translateX()` instead of `left` (the site's `left` transition triggers layout on every frame) and adds the reduced-motion fallback the site omits. → `slide-in-drawer-scrim`
- **Sticky index rail with a nested sticky title** — *Trigger:* scroll-progress. *Mechanism:* the 195px rail is `position: sticky; top: 0` with `max-height: calc(100vh - 110px)` and its own `overflow-y: auto`; inside it, the title bar is *independently* sticky to the rail's scroll box, so the label holds while the rail's 27 links scroll under it. A single element cannot both pin to the page and scroll its own content — the two-level sticky is what buys you both. *Reads as:* a table of contents that is always present and never taller than the window. *Transfers to:* docs sidebars, dashboard filter rails, any long index. *Safety:* **production-safe** (native sticky, no JS, no scroll listener).
- **Viewport-fit link distribution** — *Trigger:* load (layout, not animation). *Mechanism:* the rail's link container is `display: flex; flex-direction: column` with `min-height: 470px; max-height: 630px`, and each of the 27 links is `flex: 1 1 0`. The links share the available height evenly instead of stacking at their natural height, so the complete taxonomy fits one screen at any viewport in range without scrolling. *Reads as:* "this is all of it, and it fits." *Transfers to:* any fixed-cardinality index (chapter list, step tracker, section nav) where seeing the whole list beats seeing it at a comfortable size. *Safety:* **production-safe**, with the honest caveat that it trades line-height for completeness and can crush touch targets — the site's rail links land at ~14px tall. → **patterns_to_build: `viewport-fit-nav-rail`**
- **Color-only hover states** — *Trigger:* hover. *Mechanism:* catalog cells wash to `#edf2ed`, autocomplete rows to `#ffffb5`, buttons darken `#336633 → #3c773c`. No transform, no shadow, no scale, and on the cells no transition at all — the wash is instant. *Reads as:* immediate, mechanical, zero-latency. *Transfers to:* any grid where 1,300 elements could plausibly hover; a transform or shadow on that many candidates is a compositor bill and a visual jitter. *Safety:* **production-safe**, and the *instant* (untransitioned) hover is a legitimate choice on high-cardinality grids — a 120ms fade across a fast pointer sweep reads as lag, not polish.
- **Masthead height collapse** — *Trigger:* state (search focus / route). *Mechanism:* `.container-masthead` transitions `height 0.3s`, with the logo, search box, browse button, and nav container each transitioning their own absolute offsets over the same 300ms so the whole header recomposes into a shorter bar. *Reads as:* the chrome getting out of the way. *Transfers to:* any app shell with a tall marketing header and a short working header. *Safety:* **production-safe but costly as written** — transitioning `height`, `top`, `bottom`, and `left` on five elements is five layout passes per frame; do it with `transform: translateY()` on a wrapper and a fixed-height inner bar.

> **Honest read:** there is no choreography to distill here, and that is the finding. A site that ships 1,300 products on one screen and animates nothing except a drawer is making an argument about where design effort belongs. Cite it when someone proposes a scroll-reveal on a data-dense page.

## Production-safety note

Everything on this page is production-safe by construction — it is a 25-year-old procurement tool, not a portfolio piece. The cautions run the other way:

- **Sprite-sheet icons: production-safe, but modernize the mechanism.** Use an SVG `<symbol>` sprite + `<use>` rather than PNG `background-position`, so icons scale, recolor via `currentColor`, and survive high-DPI. Keep the one-sprite-per-group boundary.
- **Fixed-cell grid: production-safe.** Publish the cell as a token; size containers in multiples of it. Do not clip labels with `overflow: hidden` without a `title`/`aria-label` carrying the full name — this site does clip.
- **Two-level sticky rail: production-safe**, zero JS. Verify `max-height` accounts for your actual header offset or the rail will overflow the viewport.
- **Drawer + scrim: production-safe**, provided you (a) animate `transform`, not `left`; (b) gate it under `prefers-reduced-motion`; (c) trap focus and wire `Escape` — the source site's scrim is `pointer-events: none` even when open, which is a real dismissal bug to *not* copy.
- **Viewport-fit link distribution: production-safe with a tap-target cost.** `flex: 1 1 0` on nav links will compress below 44px on short viewports; clamp with `min-height` and accept a scrollbar.
- **No responsive layout: do not copy.** `viewport width=1024` and zero media queries is defensible only when you know your users are on desktops and would rather pinch-zoom a familiar layout than learn a reflowed one. Almost nobody has that license.
- **A11y remediation before reuse:** restore `:focus-visible` (and never `outline: none` on the search field), add a `prefers-reduced-motion` block, raise the 10.5px label and the rail links, and ensure every icon cell's accessible name lives in text.

## Extracted patterns

- **fixed-cell-catalog-grid** — a rigidly quantized `cell × count` tile grid (fixed cell, hairline chrome, sprite-offset icon, clipped two-line label, color-only hover) whose group widths are literal multiples of the cell so rows pack without a grid engine; reuse for icon pickers, parts catalogs, media libraries, any wall of uniform small things.
- **slide-in-drawer-scrim** — off-canvas panel + dimming scrim, transform-driven, reduced-motion-gated, focus-trapped, with the resting scrim inert (`pointer-events: none`, `opacity: 0`) so it costs nothing when closed; reuse for nav drawers, filter panels, cart flyouts. (motion)
- **patterns_to_build → `viewport-fit-nav-rail`** — a sticky index rail whose links are `flex: 1 1 0` inside a `min/max-height` column, so a fixed-cardinality taxonomy always fits one screen; nested sticky title holds while the rail scrolls internally. No recipe file yet. Build it with a `min-height` clamp on each link so tap targets survive short viewports.
