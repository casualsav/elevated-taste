## What works (transferable principles)

- **Hierarchy from scale contrast in ONE weight family, not from bolding.** Display headings jump to ~64px while body sits at 16px — a ~4× leap — yet both ride the same near-single weight (Inter 400/510). The size does the shouting, so the page reads calm even when the heading is large. Transfers to any marketing or product surface where you want emphasis without a "heavy/loud" feel: scale up, don't bold up.

- **Negative tracking on large type is what makes oversized headings feel engineered, not ballooned.** Headings carry roughly -0.022em (the raw -1.4px at 64px); at display sizes default letter-spacing looks loose and amateur, so tightening it restores the optical density a designer expects. Rule: the bigger the type, the tighter the tracking — apply a `tracking-tight` token only at `2xl`+ sizes.

- **A dark, ultra-low-chroma canvas lets a single saturated color carry 100% of the brand energy.** The whole page is near-black `#08090a` with off-white text and grey muting; color appears only as (a) muted data-viz hues and (b) exactly two loud spotlight cards (chartreuse, blue wash) in the testimonial row. Because the field is desaturated, those one or two swatches read as deliberate punctuation. Transfers anywhere you want a premium/technical mood: starve the palette, then spend color in one place.

- **On a dark canvas, build elevation from additive light, not drop-shadow.** Linear lifts its embedded product panels with a hairline top-edge rim-light drawn via `mix-blend-mode: lighten` glow layers (8 in the raw profile) rather than a cast shadow. Because a blended highlight *adds* light instead of painting a fixed color, a single rim/glow token reads correctly whether it lands on the near-black `#08090a` field or a lighter `#0f1011` surface — no per-surface shadow tuning, and the panel never looks like it's faking a shadow onto a flat page. Transfers to any dark dashboard or product-marketing surface: model depth as blended light on the leading edge, and keep drop-shadows to whisper-thin hairlines.

- **Show the product as the hero, full-bleed, instead of an illustration.** Every section pairs a short text header with a large, real screenshot of the actual app UI (issue view, gantt, scatter chart, code diff). For a tool, the interface IS the value prop; rendering it at high fidelity builds more trust than abstract art. Transfers to any developer/SaaS product — lead with a true-to-life UI capture, dark-on-dark so it melts into the page.

- **A repeating two-column section header creates rhythm across a long page.** Each feature block uses the same skeleton: big heading top-left, muted 2-line description + a tiny numbered link top-right, then the visual below. Reusing one header geometry down a 10k-px page makes a dense story feel like a system rather than a pile of sections. Transfers to any multi-feature landing page — define the header once, repeat it.

- **Functional color is muted; only data-viz and accents get chroma — and even those are pastel.** The scatter plot and status chips use desaturated blue/pink/amber/teal (`#8fa6ff`, `#f79ce0`…) rather than primary RGB. Low-saturation accents on a dark field stay legible without vibrating or screaming "alert." Transfers to dashboards: pick pastel-weight categorical colors, not pure hues, for dark UIs.

- **Semantic tint, not semantic fill, for inline status.** The code-diff and issue states use ~7–10% alpha background washes (`rgba(39,166,68,0.07)` add / `rgba(243,78,82,0.10)` delete) over the dark surface, with the text staying near-white. You get unmistakable green/red meaning without blocky candy-colored rows. Transfers to any diff, log, table-status, or validation UI.

## Design-system read

- **Type:** Two families — a system-sans (Inter Variable, Inter-class) for everything visible and Berkeley Mono reserved for code/metadata labels. Scale is a wide two-cluster set: a tight UI ramp (10/12/13/14/16/20/24px) plus display jumps (~32/48/64/72px) with almost nothing between — the gap itself is the hierarchy. Weights are the real Inter optical steps 400/510/590; hierarchy is created by **size + tracking**, never by going bold. Leading is generous for body (24px on 16px = 1.5) and near-1.0 on display. Stylistic set `ss01` + `tabular-nums` are on (tabular figures for the issue counts / changelog dates). **Tracking is not one constant em — it scales with size:** captured pairs run -1.584px@72px, -1.408px@64px, -1.056px@48px, -0.704px@32px, -0.288px@24px, -0.24px@20px, -0.182px@14px, -0.165px@15px — i.e. roughly **-0.022em at display collapsing toward ~-0.011em at UI sizes** (the bigger the type, the tighter, in em terms), not a fixed letter-spacing.
- **Color:** Dark monochrome system. `bg #08090a` → `surface #0f1011` → text `#f7f8f8` → `muted #8a8f98` → `subtle #62666d`; borders are translucent white at 5–8% alpha so dividers feel like light, not lines. Accent is a restrained periwinkle `#8fa6ff`. Categorical data hues + two spotlight brand colors are the only saturation on the page.
- **Spacing rhythm:** 8px base. Tight controls cluster (2/4/8/12px gaps, 24/32px section padding inline) with large 96px vertical breaks between feature blocks. Whitespace is the primary separator — there are very few visible dividers; air does the work.
- **Layout system:** Centered max-width container (~1024–1100px content). Repeating 2-col header (heading | description+link) over full-bleed visuals; logo wall and footer use even multi-column grids. Captured grid uses **1/2/3/4-column** spans on desktop, collapsing to **1/2 (with a 5-col footer block)** on mobile; the **5-column footer → fewer columns** and the **7-link nav → 3 links + likely hamburger** at 390px. Viewport captured at 1440×900 (mobile probe at 390px).
- **Layering / page architecture:** Mostly a single flat scroll over a shallow, deliberate z-stack. Only the nav chrome is `position: fixed` above the flowing page (see Motion); sections otherwise stack in one column. The depth that reads as "premium" comes from two devices, not from shadows: (1) the embedded **product-UI mocks are lifted onto raised translucent surfaces whose top edge catches a hairline rim-light** — a lighter ~1px highlight along the upper border, visible on every panel in s00/s01/s05 — drawn with **`mix-blend-mode: lighten` glow layers** (8 elements, `_glow` classes in the raw profile) so the rim reads as *light* on whatever tone sits beneath it (the same highlight lands correctly on `#08090a` bg and on a `#0f1011` panel); alongside them, **11 `mix-blend-mode: overlay` grain layers** (`_grain`/`_grainSubtle`) lay a film-grain texture into panel surfaces so the dark fields read as material rather than flat fill; (2) **overlays dim the layer beneath with a scrim** — the composer and the "Assign to…" menu (s03/s05) float above the panel and darken everything under them so focus tracks the topmost layer. Net: depth is carried by *additive light + scrim*, with drop-shadows kept whisper-thin (see Restraint). Transfers to any dark product surface — express elevation as an additively-blended top-edge highlight (one rim token then works at every surface depth) and dim-behind rather than shadow-in-front for popovers.
- **Grid / container:** column spans **1·2·3·4** desktop → **1·2·5** mobile (5-col footer is the densest block); re-probe measures the content container at **~1280px** centered (~80px side margins on the 1440 frame; the two-column feature header is two ~540px columns inside it), with the product-UI mocks breaking slightly wider (~1340px, near-full-bleed). Intra-list/issue gutters are small (**~8px**); section gutters are whitespace, not rules. (`.craft.grid.columns` = ["1","2","3","4"] — present, not frame-estimated.)
- **Motion / easing intent:** Quick, restrained. Captured durations cluster at **100 / 160 / 200ms** (hover/state) with a **400ms** for larger reveals; easings are `cubic-bezier(0.25,0.46,0.45,0.94)` (ease-out-quad, the workhorse) and `cubic-bezier(0.165,0.84,0.44,1)` (ease-out-quart, longer settle), plus bare `ease`/`ease-out` for trivial fades. In-view reveals fire from IntersectionObserver at thresholds **0.3/0.5** with a generous **250px rootMargin** (start before fully in view); stagger steps **100/200/300/400ms** but `staggeredEntrance` was not observed firing on the homepage. Motion communicates responsiveness (snappy hovers) and a faint "alive" hum (an ambient dot-grid loop), never spectacle. Full choreography in **Interaction & motion** below.
- **Density:** High — the embedded product shots are genuinely data-dense (issue lists, gantts, scatter plots) — yet legible because the marketing chrome around them is sparse and high-contrast.
- **Hierarchy:** Dominant ordering device is **scale** (display vs body gap), reinforced by position (left-aligned headers) and the dark→light value contrast.
- **Restraint:** No gradients on text, no drop-shadow-heavy cards, no multiple type weights competing, no rainbow accents. Shadows are whisper-thin (`0 1.2px 0 rgba(0,0,0,0.03)`) or inset hairlines. Color is rationed to two cards.
- **Components (captured states):**
  - **Nav item (button/link):** rest `color #8a8f98` (muted) on transparent; **hover** → `color #f7f8f8` (full white) + `background rgba(255,255,255,0.08)` — a recolor-plus-faint-fill, no movement. **Focus** → `outline 1px #5e69d1` (periwinkle), the same ring on every interactive.
  - **Sidebar / list button:** rest transparent; **hover** → barely-there `background rgba(255,255,255,0.02–0.03)` (a 2–3% white wash, even quieter than nav). This is the house "you can click this" whisper.
  - **Primary CTA / send button:** the send-button group reveals on in-view (`opacity 0.2→1`) and fills to the periwinkle `rgb(94,106,210)`; the marketing CTAs ("Get started" light pill / "Sign up") are solid off-white on dark.
  - **Skip-to-content link:** the one element with a heavy focus treatment — `outline 1px #5e69d1` **plus** a double ring `0 0 0 2px #08090a, 0 0 0 4px rgb(94,106,210)` (bg-colored inner + periwinkle outer) so it pops when keyboard-revealed.
  - **Disabled:** **weak — flag it.** Captured disabled state keeps `opacity 1`, `background rgba(255,255,255,0.03)`, full-white text, and **`cursor: pointer`** — i.e. it reads almost identical to rest and still signals clickable. Don't copy this; a real disabled state needs reduced opacity / `cursor: not-allowed` / `aria-disabled`.
- **A11y (honest, incl. defects):** `prefers-reduced-motion` **respected** (1 PRM rule; the dot-grid + reveals gate off). **`focus-visible` present** — consistent 1px periwinkle ring on all interactives, double-ring on the skip link (good). **Image alt coverage is perfect: img_alt_ratio = 1.0** across 32 images. **Defects:** (1) **146 of 170 interactive elements register as small tap targets (<44px)** — a real mobile-ergonomics gap on a dense product chrome; (2) the **disabled state is visually indistinct** (see above); (3) muted/subtle greys `#62666d`/`#8a8f98` on `#08090a` are borderline for small body text — keep `#8a8f98`+ and size up.

## Interaction & motion

Linear's motion is **restraint with one ambient flourish** — the page is largely static at rest (every hero/feature block is fully composed in frame s00; the two-tone headlines and spotlight quote-cards are baked, not animated), and the only "wow" is a looping dot-grid behind the product demos. Evidence from the capture: **82 `@keyframes` but ~58 of them are `grid-dot-R-C-upDown / -pong / -agent`** (one ambient background system, not 82 distinct effects), 182 CSS animation rules, **3 IntersectionObservers over 74 targets**, 139 `requestAnimationFrame` calls in one scroll pass, 9 scroll + 12 mousemove listeners, **0 detected libraries (hand-rolled), 0 canvas, 0 video**, 17 marquee elements, 7 disclosures, and **1 `prefers-reduced-motion` block — reduced motion is respected.** Stack: `IntersectionObserver` · CSS `@keyframes` · pinned (`position: fixed`) header. No GSAP / Lenis / Framer.

- **Sticky-pinned chrome (header + skip-link)** — *Trigger:* scroll-progress. *Mechanism:* the top nav and the skip-to-content link are `position: fixed`, so they hold while the entire ~10k-px page scrolls beneath (visible: the header sits identically in s00→s10). *Reads as:* a stable frame around a long scroll; wayfinding always in reach. *Transfers to:* any tall marketing/docs page. *Safety:* **production-safe** (native fixed, no JS, no reflow). → `sticky-pin-scrollytelling` (the simplest case of it).
- **In-view fade-rise reveal** — *Trigger:* in-view (IO, 74 targets, thresholds 0.3/0.5, 250px rootMargin). *Mechanism:* one class flip on intersect drives a CSS `opacity` (+ small `translateY`) transition, fired once as a block enters; the send-button group is the clearest captured instance (`opacity 0.20→1.00`). *Reads as:* a long page that "settles in" section by section rather than all-at-once. *Transfers to:* any tall page wanting entrance rhythm without scroll-jank. *Safety:* **production-safe** (GPU-cheap opacity/transform, once-only, reduced-motion-gated). → `scroll-reveal-in-view`.
- **In-view control "arming" (fade + background-shift)** — *Trigger:* in-view. *Mechanism:* the demo's send button both fades up **and** shifts background from transparent → the periwinkle `rgb(94,106,210)` as it enters, so the primary action visibly "turns on." *Reads as:* the interactive surface coming alive / inviting the next click. *Transfers to:* a hero CTA or form submit you want to feel armed when it scrolls into view (pair sparingly with the fade so it isn't gaudy). *Safety:* **production-safe** (color/opacity transition; ensure the control is usable in its resting color too, since reduced-motion ships the end state). → `scroll-linked-recolor`.
- **Ambient animated dot-grid backdrop** — *Trigger:* load (looping), behind product demos. *Mechanism:* a 5×5+ matrix of dots each runs its own keyframe (`grid-dot-{row}-{col}-upDown / -pong / -agent`) for a slow drifting/pulsing field; corroborated by the dotted `repeating-linear-gradient` (3px on / 4px off) in the elevation gradients and the faint grid visible under the lower feature blocks (s05/s08). The `-agent` variant implies a state where the field reacts to the "agent" demo. *Reads as:* a quiet "the system is live / computing" hum under otherwise static screenshots — craft signal, not decoration. *Transfers to:* dark dev-tool / AI heroes wanting ambient life without a heavy canvas scene. *Safety:* **spectacle-leaning but cheap if budgeted** — ~58 simultaneous CSS animations is real compositor work; keep it transform/opacity-only, cap the node count, **pause off-screen**, and gate under reduced-motion (Linear does). No standalone recipe — bespoke per content. → **patterns_to_build: `ambient-dot-grid-loop`.**
- **Hover recolor / faint-fill (no movement)** — *Trigger:* hover. *Mechanism:* nav links go muted→white (`#8a8f98→#f7f8f8`) with a `rgba(255,255,255,0.08)` background; sidebar buttons get an even quieter `rgba(255,255,255,0.02–0.03)` wash. Pure color/background, **no transform** — the restraint is the point. *Reads as:* responsive and precise without bounce. *Transfers to:* all interactive chrome on a dark surface. *Safety:* **production-safe**. (No file — `hover-recolor` is a house micro-state; see motion-key.)
- **Logo-wall / status marquee** — *Trigger:* load (continuous). *Mechanism:* the customer logo row and status-stream chrome ride a horizontal ticker (17 marquee elements detected; logo wall visible in s01). *Reads as:* social proof / live activity scrolling past. *Transfers to:* logo walls, ticker bars, "now playing" status. *Safety:* **production-safe** if it pauses on hover/focus and respects reduced-motion. → `announcement-ticker-marquee`.

> **Honest read:** apart from the dot-grid loop and the marquees, this homepage barely moves — its polish is in *typography, value contrast, and real-UI screenshots*, not choreography. The 82-keyframe count is inflated by the per-dot grid system; don't read it as a heavily animated page.

## Production-safety note

All techniques here are **production-safe** — this is a real shipping product site, optimized for clarity and performance:
- Dark monochrome + 1 accent: **production-safe**. A11y caveat — verify muted/subtle greys (`#62666d` on `#08090a` ≈ borderline) meet 4.5:1 for body text; use `#8a8f98`+ for anything small.
- Scale-driven hierarchy in one weight: **production-safe**, zero cost.
- Translucent-white borders/low-alpha semantic tints: **production-safe**; cheap, and they auto-adapt to surface depth.
- Full-bleed real-UI screenshots: **production-safe** but a **payload/perf watch** — these are large images; ship responsive `srcset`/AVIF and lazy-load below the fold (this page is ~10k px tall).
- Spotlight saturated cards: **production-safe** precisely because they're rare; the technique fails if copied onto many elements (the rationing IS the design).
- Motion: sticky chrome, in-view fade-rise, hover-recolor and the marquees are all **production-safe** (reduced-motion-gated). The **ambient dot-grid loop** is the one **spectacle-leaning** item — ~58 concurrent CSS animations is genuine compositor load; budget the node count, pause off-screen, and ship the static grid under reduced-motion (Linear does).
- A11y watch on motion: because reduced-motion ships the *end* state, controls that "arm" via in-view background-shift must be usable in their resting color too.

## Extracted patterns

- **feature-section-header** — the repeating two-column heading-left / description+numbered-link-right block that sits above each product visual; reuse to give a long multi-feature page a consistent spine.
- **spotlight-quote-card** — a testimonial/quote card that uses one saturated fill against an otherwise monochrome page; reuse to spend color deliberately and draw the eye to social proof.
- **sticky-pin-scrollytelling** — fixed header/chrome that holds while a tall page scrolls beneath (Linear uses the degenerate "just pin the nav" case); reuse for persistent wayfinding on long pages. (motion)
- **scroll-reveal-in-view** — IntersectionObserver-gated fade+rise that fires once per block; reuse to give a long page entrance rhythm without scroll-jank. (motion)
- **scroll-linked-recolor** — a control/region shifts color/background on entry (Linear "arms" its send button to periwinkle); reuse to add a second beat to a reveal or make an action feel live. (motion)
- **announcement-ticker-marquee** — infinite horizontal ticker (logo wall / status streams) that pauses on hover/focus; reuse for social-proof rows and live-status bars. (motion)
- **patterns_to_build → `ambient-dot-grid-loop`** — a matrix of individually-keyframed dots (`upDown`/`pong`/`agent` variants) forming a slow pulsing backdrop behind dark product demos; no recipe file yet. Build it transform/opacity-only, node-capped, off-screen-paused, reduced-motion-gated.
