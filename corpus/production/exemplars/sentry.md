## What works (transferable principles)

- **One dark monochromatic field, broken by playful artifacts — not by surfaces.** The entire page sits on two near-identical deep indigos (`#150f23` / `#1f1633`); there are almost no light sections or contrasting bands. Calm and continuity come from the single dark field, while *personality* is injected as discrete objects on top of it — a hand-drawn squiggle divider, mascot illustrations, a lone saturated-purple panel. Transferable: you can run a long page on one background color if you place a few high-character objects to mark beats; you don't need alternating surfaces to create rhythm.
- **A two-tier color system: a tiny UI accent set, and a separate "illustration/data" palette kept off the chrome.** The chrome uses essentially one accent — magenta-pink `#ff45b2` for the headline emphasis word, section subheads, footer labels, and the outline-CTA border. The vivid coral/sky/lavender/lime/green you see live *only* inside product-UI mocks and the mascot art. Holding the rainbow inside the "content" and rationing the UI to one pink keeps the page from looking like a toy while still feeling colorful. Transferable rule: namespace your charting/illustration colors away from your UI accent tokens so the playful palette can't leak into buttons and labels.
- **Hierarchy is scale + color, in one weight family.** The display headline ("Code **breaks**, fix it faster") jumps to ~60–88px against 16px body — a ~4–5× scale leap — and the emphasis is carried by *coloring one word pink*, not by a heavier weight. Body runs at a single regular weight. Transferable: lead with scale contrast and a single colored word for emphasis before reaching for bold; it reads calmer and more designed at high density.
- **Show the real product as the hero art, feathered into the dark.** The hero and feature sections are literal dark renders of Sentry's dashboards (stack traces, "Root Cause", session replay) flanking the copy. A same-color glow shadow (`0 0 8px 6px #150f23`) feathers each mock's edge into the background so it reads as embedded, not pasted. For a dev tool the product screenshot *is* the most persuasive image available. Transferable: drop real UI on the page and dissolve its border with a background-matched glow instead of a hard frame or drop shadow.
- **Brand voice lives in the structural furniture, cheaply.** The footer's section break is a hand-wobbled squiggle instead of an `<hr>`, and the final CTA ("Fix It") switches to a chunky custom slab display face for its headline *and* its paragraph. Neither spends layout or color budget; both are register shifts that make a systematic page feel human. Transferable: express personality in the dividers, the closing beat, and the illustrations — the places where a default would otherwise sit — and keep the body grid strict.
- **Mascots carry the emotional register a B2B dev tool usually suppresses.** Hand-drawn characters (astronaut, the panicked-at-the-CRT scene) appear at section transitions and the newsletter block. They make "your code is broken" feel friendly rather than anxious, differentiating an otherwise standard observability product. Transferable (with restraint): a small recurring illustrated cast can humanize a technical product, but it must be rationed to a few placements so it stays a signature, not clutter.

## Design-system read
- **Type:** Rubik (geometric sans) is the sole workhorse — 16px body, scale climbing to ~60/88px display at line-height ~1.1 (88px head measured at 105.6px leading). Hierarchy is **scale-driven** within mostly one weight (400, with 500/700 for labels and headings). **Tracking stays at ~0 (normal) across sizes** — the captured `tracking_by_size` shows the 88px h1 at `normal` and the 27px subhead at 0%, so this geometric face does *not* use the "bigger = tighter" negative-tracking trick (Rubik's drawing already reads tight at scale); don't impose a `tracking-tight` token here. Two mono faces (Monaco, IBM Plex Mono) are reserved strictly for code inside product mocks. A custom slab display, "Dammit Sans," is used in exactly one place — the "Fix It" closing block — as a voice-shift, never as body copy.
- **Color:** Dark, near-monochromatic indigo base (`bg #150f23`, `surface #1f1633`); one saturated `surface-2 #3c1878` panel (newsletter). UI accent is rationed to magenta-pink `#ff45b2`; an electric violet `#7553ff` fills primary buttons. A six-hue coral/sky/blue/lavender/lime/green set is namespaced as illustration/data color and never touches chrome. fg pure white; grays ramp `#d4d4d4 → #9298a8 → #6a737d`; borders are white at ~12%.
- **Spacing rhythm:** 8px base; tight inner gaps (4/6/8px) inside dense product cards, large section padding (44/64px blocks) to keep the dark field breathing between beats.
- **Layout system:** Single max-width centered column (~1280px) of stacked full-width sections on one background; hero is a centered headline flanked by product mocks. Footer is a 4-column link grid with pink section labels. Collapses to a single column on mobile (1170px capture is a long single-column stack).
- **Grid / container:** captured `grid.columns` are **1 and 2** at desktop (1440 vw) — the page is built from single-column stacks and 2-up splits (copy ↔ product mock, the "Loved by developers" row is a 3-up testimonial set inside a 2-col shell), inside a centered container that tops out ~1280px. On mobile (390 vw) the grid resolves to **1 and 3** columns (the footer link grid stays multi-column where the hero/feature splits flatten to one). Component gaps run tight (4/6/8px) inside product cards; section padding is the macro rhythm (44/64px blocks). Gap values are frame/profile-consistent; exact gutter px not isolated.
- **Components (from captured states):**
  - **Button** — primary is the electric-violet `#7553ff` fill (white text); secondary/CTA is an outline ringed in accent pink `#ff45b2`. **No hover delta was captured** (`hoverEffects: 0`) — hover is either a sub-200ms `cubic-bezier(0.4,0,0.2,1)` tint not sampled at the scroll stops, or genuinely minimal; treat hover styling as *unspecified by the capture*, don't fabricate a lift. **Disabled:** `opacity 0.25`, bg `#2d2340` (raised indigo), white text, `cursor: not-allowed`.
  - **Card** (product-mock panels) — `surface #1f1633` on the `#150f23` field, ~10–18px radius, edges feathered by the same-color glow `0 0 8px 6px #150f23` (no border, no elevation shadow). State changes are scroll-entrance reveals, not hover.
  - **Nav** — sticky top bar; 42 links desktop → 37 mobile with a hamburger collapse; pink (`#ff45b2`) section labels in the footer grid. No per-item hover delta captured.
  - **Input** (newsletter / forms) — dark fields on the saturated `#3c1878` panel; **focus is a 2px `#4f46e5` indigo outline** (`focus_visible: true`) — note this ring is indigo, *not* the brand pink, so the focus color is off-system (likely a framework default) and could be repointed to `accent` for brand consistency.
- **Motion / easing intent:** Captured params — durations cluster at **150 / 200 / 300ms** for micro/state, **750 / 800ms** for entrance reveals, with two long ambient loops (**2000ms** and a **60000ms** logo-belt cycle); a single **400ms** stagger delay. Easings are mostly Material `cubic-bezier(0.4,0,0.2,1)` plus `ease-out`, `cubic-bezier(0,0,0.2,1)` (decelerate) and `cubic-bezier(0.25,0.46,0.45,0.94)` (easeOutQuad) — no bespoke house curve. The base micro-motion reads as "content arriving," not spectacle; the page's full choreography (sticky header/pinned toggle, logo-belt parallax+rock, mascot float, in-view product reveals) is detailed in **Interaction & motion** below.
- **Density:** High *within* the product mocks (real dashboards), low in the marketing copy. The two registers are kept visually separate (dense UI in framed glows, airy type in the open field) so neither fatigues the eye.
- **Hierarchy:** Dominant ordering device is **scale**, with **color** (one pink word) for in-line emphasis; surfaces stay constant, so they do no hierarchy work.
- **Restraint:** No alternating light/dark bands; no gradients on chrome; no drop-shadow elevation (the only shadow is a same-color feathering glow); the rainbow palette is deliberately confined to illustrations; the custom display face appears exactly once.

## Interaction & motion

Sentry's motion is **light and ambient, not scroll-scrubbed** — a sticky chrome layer, a self-running logo belt, drifting mascots, and once-only in-view reveals, all hand-rolled (no GSAP/Lenis/Framer in the fingerprint). Evidence from the capture: **10 `@keyframes`** (`fade-in`, `float`, `logo-rock`, `scroll-x`, `expandSnippet`/`shrinkSnippet`, `swingDown`, `pushUp`, `_spin_…`, `_thumbRotation_…`), 9 CSS animation rules + 41 transition rules, **2 IntersectionObservers** over 2 targets (threshold 0.25), 4 scroll listeners, ~**1031 rAF calls** in one pass (the continuous belt/float loops, not scrubbing), 1 `<canvas>`, 19 disclosure widgets — and **0 hover effects, 0 cursor-followers, 0 tabs/carousels**. **3 `prefers-reduced-motion` blocks → reduced motion is respected.** Stack: `IntersectionObserver` · CSS `@keyframes` + transitions. (Dropped as noise: the `breaks,` entrance entry, captured `from==to`; and the `grecaptcha-badge` fixed-pin, a vendor widget.)

- **Sticky chrome + pinned mode toggle** — *Trigger:* scroll-progress. *Mechanism:* the header (`position: sticky`) and a "Marketing Mode" toggle (`position: fixed`) hold their viewport slots while the page scrolls — confirmed by frames: the nav and the top-right toggle sit in the identical position across s00 → s01 → s06 → s09. *Reads as:* persistent wayfinding + a playful always-there "mode" control that signals the page knows it's a marketing surface. *Transfers to:* any long marketing page wanting a persistent nav and one floating utility affordance. *Safety:* **production-safe** (native sticky/fixed, no JS). → `sticky-pin-scrollytelling`.
- **Self-running logo belt (auto-scroll + rock)** — *Trigger:* load (continuous), nudged by scroll. *Mechanism:* the customer-logo row (`div.logo-item` / `span.logo-content`) translates horizontally on the `scroll-x` keyframe (~60s loop) with a small `logo-rock` tilt — the capture also reports a **−1.4° rotate** and parallax `transform` on `logo-content`. *Reads as:* a living "trusted by" belt rather than a static logo wall (seen forming at the base of s01: sentry / baseten / Runlayer / convex / supabase / GitHub). *Transfers to:* social-proof logo strips, marquee tickers. *Safety:* **production-safe** (compositor-only transform; pause on hover/focus and under reduced-motion). → `announcement-ticker-marquee` (closest belt recipe) + `parallax-drift` (the rock/drift).
- **Mascot float / parallax drift** — *Trigger:* load (ambient) + scroll-progress. *Mechanism:* the hand-drawn characters ride the `float` keyframe (gentle bob) and translate at a different rate than the copy as you scroll — visible as the astronaut's boots drifting between the hero and the logo wall in s01. *Reads as:* the illustrated cast feels alive and weightless, carrying the friendly register. *Transfers to:* decorative illustration layers, hero ornaments. *Safety:* **production-safe** (transform/opacity only; gate under reduced-motion so the art rests). → `parallax-drift`.
- **In-view product-mock reveal** — *Trigger:* in-view (IO, threshold 0.25, 2 targets). *Mechanism:* feature dashboards enter on a `fade-in` keyframe with a ~750–800ms `ease-out` settle as their section crosses 25% visibility (the dark "Root Cause" / replay panels easing in from the right edge in s02–s03). *Reads as:* "evidence arriving" — each claim lands with its product proof. *Transfers to:* any feature section pairing copy with a screenshot. *Safety:* **production-safe** (one-shot, GPU-cheap, reduced-motion gated). → `scroll-reveal-in-view`.
- **Code-snippet expand/collapse** — *Trigger:* in-view / disclosure (19 disclosure widgets). *Mechanism:* "five lines of code" install snippets grow and shrink on the `expandSnippet` / `shrinkSnippet` keyframes (paired with `swingDown` / `pushUp` for the entering/exiting blocks) to demo the "monitor in five lines" beat (s02). *Reads as:* the install story animating itself — show, don't tell. *Transfers to:* code-walkthrough heroes, onboarding step reveals. *Safety:* **production-safe**, but animating snippet *height* can reflow — prefer transform/clip and reduced-motion-jump-to-end. → `clip-reveal` (use clip/transform instead of height for the production version).

Mousemove listeners are present (9) but with **0 cursor-followers and 0 hover effects captured** they read as form/toggle handlers, not a pointer-trailing effect — so no magnetic/cursor technique is claimed. The lone `<canvas>` and `_spin_` / `_thumbRotation_` keyframes drive a small UI control (a toggle/loader), not a hero WebGL scene.

## Production-safety note
- **Hand-drawn squiggle divider** — production-safe. Decorative, `aria-hidden`, one tiny inline SVG; no motion/perf/a11y cost. Caution: keep amplitude/stroke low so it never competes with content.
- **Display-font closing CTA** — production-safe *if the font is handled*. The risk is webfont weight for ~10 glyphs: subset the custom face, `font-display: swap`, lazy-load (it's at page bottom), and never make it render-blocking. Keep it at display scale only (decorative slabs are illegible small).
- **Same-color glow on product mocks** — production-safe. A blurred shadow in the background color; cheap, no a11y impact. Avoid stacking many on screen at once (paint cost of large blurs).
- **Mascot illustrations** — production-safe; ship as optimized SVG/static art with `alt`/`aria-hidden` as appropriate. Cost is asset weight and tone-fit, not technical.
- **Sticky header + fixed mode toggle** — production-safe (native sticky/fixed). Watch: a persistent fixed toggle eats top-right space on small viewports — make sure it can't overlap the hamburger; keep it keyboard-reachable.
- **Self-running logo belt + mascot float** — production-safe *if gated*: compositor-only transforms, but they animate forever, so **pause on hover/focus and disable under `prefers-reduced-motion`** (Sentry ships 3 PRM blocks). Continuous motion near reading copy is a mild motion-sickness/attention cost.
- **In-view reveals + snippet expand/collapse** — production-safe; the one caveat is the snippet `expand/shrink` if it animates real height (reflow) — animate transform/clip and jump to end-state under reduced motion.

## Accessibility (captured)
- **Alt text:** **img_alt_ratio = 1.0** — all 43 images carry alt text. Strong; keep decorative mascots `aria-hidden` so they don't add noise.
- **Focus-visible:** **present** (`focus_visible: true`) — but the ring is a **2px `#4f46e5` indigo** outline, *not* the brand pink; it's likely a framework default and slightly off-system. Functional and visible on the dark field; consider repointing to the `accent`/`accent-violet` token for brand fit.
- **Reduced motion:** **respected** — 3 `prefers-reduced-motion` blocks; the ambient belt/float should rest under it.
- **Tap targets:** **defect** — **107 of 288** interactive elements (~37%) are below the 44px target, concentrated in the dense product-mock UI and the 42-link nav/footer. Acceptable inside decorative product *mocks* (not really operable), but the real nav/footer links should be bumped to ≥44px hit area on touch.
- **Dark mode:** the site *is* dark by default (`supportsDark: true`); no light theme to audit.
