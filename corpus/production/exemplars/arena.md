## What works

- **The landing page is a document, not a pitch.** No hero, no `<h1>` at all, no feature triptych, no screenshot-on-gradient. The page is ~450 words of first-person prose in one centered column, set at body size, and the *argument* is the conversion mechanism: it defines the product in two numbered clauses, quotes how users describe it, states the price, then spends the rest of the page on a philosophy of attention. Transfers to any product whose value is an **idea rather than a screenshot** — dev tools, research software, community products, anything where a six-word headline would flatten the proposition into a lie. The cost of a hero is that it forces you to commit to a claim you can't defend in six words; prose lets you make an argument instead.

- **Hierarchy with zero scale contrast.** The design system defines nine type steps up to `3rem`, and the homepage spends **none** of them: everything is `16px`, and section headings ("Long-term vision", "The Secret") are `16px` **bold**. Ordering comes entirely from **position, weight, and silence** — chapters are separated by ~130px of nothing. This is the exact inverse of the usual advice (a 4–6× display-to-body jump), and it works for the same underlying reason: hierarchy needs *one* unambiguous ordering device, not three. Reach for it whenever the content is genuinely linear and the reader has already opted in to reading.

- **Hover is more ink, not another hue.** Body ink is `#333`; the true `#000` is held in reserve as the **hover state**. Interactive elements darken toward black and grow a `1px` hairline border that was already there at `transparent`, so hover never reflows the box. One idea — "engaging with this makes it more present" — expressed with two neutral values and no color. Transfers to any restrained UI that wants live affordances without a brand hue in every hover.

- **One numbered neutral ramp, aliased into roles, gives four themes for free.** `--colors-gray0…gray7` is the whole neutral system; **components never name a gray**, they name `--colors-background` (`= gray0`), `--colors-foreground` (`= gray7`), `--colors-link`, `--colors-slate`. A single class on `<html>` re-points the ramp and the site becomes light / dark / dawn / dusk. Crucially the ramp *inverts* rather than shifts: on dark, `gray0` becomes `#000` and `gray7` becomes `#FFF`, so every alias keeps meaning what it meant. Even **blend mode is a token** (`--colors-blend: multiply | screen`), so `mix-blend-mode` on inline-code chips stays correct in both directions. This is the most portable thing on the site → `semantic-ramp-theming`.

- **One variable font does four jobs.** A single typeface (`areal`) serves sans, mono (`font-variation-settings: "MONO" 75` inline / `100` for blocks), italic (`"slnt" -12`) and a custom **dark-mode axis** (`"DRKM" 0|1`, set globally from the theme token) — instead of loading a sans + a mono + italic + bold cuts. Four roles, one `woff2`, and typographic register becomes a *variable-axis* decision rather than a font-loading one. Transfers to any team maintaining a design system on a real performance budget.

- **Pricing is a sentence, not a table.** Two bordered rows sit **inline in the paragraph flow**, directly after "If this speaks to you, try it now:" — plan name, one line of scope ("Up to 200 total blocks."), prices as right-aligned buttons. No three-column comparison grid, no checkmark matrix, no "Most popular" ribbon. When there are ≤2 plans and the difference is a single quantity, a table is ceremony that manufactures a decision the user doesn't have. → `prose-manifesto-landing`.

- **Restraint as the entire visual budget.** Rendered elevation: **zero shadows, zero gradients** (a shadow token exists and goes unused). One radius (`3px`). Two weights (400/700). And *no chroma anywhere in the body* — the only saturated surfaces on the whole page are the deep navy footer (`#00075F`) and the focus ring (`#3D46C2`). Holding color back until the footer is what makes the footer land as an ending rather than a chrome band.

## Design-system read

- **Type:** One family (`areal`, variable), one visible ratio. The *system* ladder is `0.78125 / 0.9 / 1 / 1.2 / 1.5 / 1.75 / 2 / 2.5 / 3 rem` (≈1.15–1.25× steps — unusually fine-grained), but the **homepage uses only the bottom three**: `16px` body @ `1.45` leading (`23.2px` measured), `14.4px`, `12.5px` captions/labels. Weights: `400` and `700`, nothing between. Hierarchy = weight + position + whitespace; scale contributes nothing. Italic and mono are variable axes (`slnt -12`, `MONO 75/100`), not separate files.
- **Color:** A single 8-step neutral ramp (`#FFF · #F7F7F7 · #EDEDED · #DEDEDE · #999 · #696969 · #333 · #000`) aliased to roles — `background = gray0`, `foreground = gray7`, `link = gray6 (#333)`, `slate = gray5 (#696969)`. Page ink is `#333`; `#000` is reserved for hover/emphasis. Hairlines are `#DEDEDE`, tinted surfaces `#F7F7F7`. Chroma is rationed to two places: `brandDark #00075F` (footer ground) and `focus #3D46C2` (focus rings only). Parallel ramps exist for semantic channel states (red/green/blue at 3 tints each) but never appear on this page.
- **Spacing rhythm:** Base `5px`, on a **deliberately non-doubling** scale: `5 · 10 · 15 · 20 · 25 · 35 · 45 · 65 · 80 · 100 · 130`. Additive at the micro end (component padding), roughly ×1.35 at the macro end (page rhythm), so you get fine control inside a row *and* real silence between chapters. The same eleven values serve as both `--space-*` and `--sizes-*`. Whitespace is the page's loudest instrument: `~130px` between essay sections, `100px` of footer padding.
- **Layout system:** A 12-column grid (`repeat(12, 1fr)`, `15px` gutters) with `65px` page padding — but only one column-span is ever used for content: the prose sits in a centered span measuring **~650px (≈80ch)** at 1440. Everything else on the page (carousel, plan rows, footer) inherits that same measure or the full grid; nothing floats free. Breakpoints at `520 / 900 / 1200 / 1800`; at ≤900 the 12-col grid collapses to `1fr`, at ≤520 page padding drops `65px → 15px` and the plan rows go column-stacked. Body size never changes across viewports — the *measure* narrows, the type doesn't.
- **Layering / page architecture:** **Single flat scroll.** No static backdrop, no blend overlay, no glass, no parallax (`has_static_backdrop: false`, `has_blend_overlay: false`; the only `mix-blend-mode` in the system is on inline-code chips). Three fixed layers exist and all three are pure chrome: a `2px` route-progress bar (`z:200`), the `55px` transparent top nav (`z:100`), and an empty toast region (`z:2147483647`). The page has exactly one surface, and content scrolls over nothing.
- **Motion / easing intent:** Motion exists only to acknowledge input or to report system state. Durations cluster at `50 / 100 / 125 / 200 / 250ms` on `ease-out` / `ease-in` / `ease`; the only long timing on the page is a deliberate `60s` asymptotic creep on the loading bar. Nothing enters, nothing reveals, nothing parallaxes. Reduced motion is **respected** — and notably, exposed as a **first-class user preference** (`html[data-reduced-motion="true"]`) in addition to the OS-level `@media (prefers-reduced-motion: reduce)` query, so a user can opt out of motion without changing their operating system.
- **Density:** Low by area, high by meaning. One column of ~450 words across a 2600px page is spatially sparse, but every element is load-bearing: there is no decorative object anywhere on the page. Legibility comes from the ~80ch measure and `1.45` leading.
- **Hierarchy:** **Position first, weight second.** (Scale: unused. Color: unused.) You read top-to-bottom because there is exactly one path.
- **Restraint:** No `<h1>`. No hero. No feature cards. No gradients. No shadows. No testimonials, no logo wall, no social proof beyond one honest number ("20,516 people support Are.na"). No dark-pattern pricing. They did not use their own type scale.

## Interaction & motion

This site is **deliberately near-static**, and unlike sites where that's a gap, here it is the thesis: a tool about sustained attention refuses to compete for it. The homepage has **no entrance reveals, no scroll-linked effects, no parallax, and no cursor effects** (`rafCalls: 0`, no libraries, no canvas). What motion exists is either a system report or a hover acknowledgement. Stack: hand-rolled — CSS transitions, CSS `@keyframes`, `IntersectionObserver` (used only for lazy media, `rootMargin: 200px` across 28 targets — i.e. *prefetch*, not reveal).

- **Asymptotic route-progress bar** — *Trigger:* load / route change. *Mechanism:* a `2px` full-width bar animates `translateX(-100% → 99%)` over **60s** on `cubic-bezier(0, 1, 1, 1)` — an ease that leaps forward instantly and then crawls, so the bar is always visibly *near* done and never actually arrives; on completion a `transform 250ms ease-out` + delayed `opacity 125ms ease-in` retires it. *Reads as:* "something is happening, and I won't lie to you about how long." *Transfers to:* any indeterminate wait — route transitions, uploads, long queries — where a fake percentage would be a lie and a spinner says nothing. *Safety:* **production-safe** (compositor-only transform; single element). → `asymptotic-progress-bar`.
- **Border reserved at transparent, revealed on hover** — *Trigger:* hover / focus-visible. *Mechanism:* buttons and links carry `border: 1px solid transparent` at rest; hover swaps only `border-color` (→ `#DEDEDE`) and `color` (`#333 → #000`). Because the border already occupies the box model, nothing reflows and no `transform` is needed to fake stability. *Reads as:* the control was always there; you just brought it into focus. *Transfers to:* every ghost/tertiary button and text link in a low-chrome UI. *Safety:* **production-safe** (paint-only, zero layout). The same swap drives `:focus-visible`, so the keyboard state is the hover state plus the accent — one mechanism, two affordances.
- **Decode-gated image fade** — *Trigger:* load. *Mechanism:* the media element ships at `opacity: 0` and is flipped to `1` once the image has actually decoded, so you never see a half-painted or reflowing image; separately an `IntersectionObserver` with a `200px` `rootMargin` starts the fetch *before* the element reaches the viewport. *Reads as:* images "were always there," never pop. *Transfers to:* any content-heavy feed. *Safety:* **production-safe** (opacity only). Note this is a *load* fade, not an in-view reveal — the element is already visible; only its paint is gated.
- **Opacity-only skeleton pulse** — *Trigger:* load (pending state). *Mechanism:* a placeholder box tints `gray1`, and an `::after` overlay of `gray2` pulses `opacity 0 ↔ 1` on a `500ms alternate infinite ease-in-out` loop. No gradient, no sweeping highlight, no `background-position` animation — one composited property. *Reads as:* patience, not urgency. *Transfers to:* any loading list. *Safety:* **production-safe**, but it is an infinite animation — it must be (and here is) covered by the global reduced-motion kill switch.
- **Masked scrim instead of a hard bar edge** — *Trigger:* none (static layering). *Mechanism:* a fixed bottom bar paints its background via a `::before` at `166%` height carrying a multi-stop `linear-gradient` **`mask-image`**, so page content dissolves under the bar rather than colliding with an edge. *Reads as:* the bar is atmosphere, not a lid. *Transfers to:* any sticky footer/toolbar over scrolling content — cheaper and softer than `backdrop-filter`, and it doesn't blur the text. *Safety:* **production-safe** (no filter cost, no compositing surprise).

**Evidence corrections (the probe is wrong here; the code and screenshot win).** The profile reports `respectsReducedMotion: false`, `keyframeCount: 0` and `prmRules: 0` — but the stylesheet contains **both** a `@media (prefers-reduced-motion: reduce)` global kill switch *and* a `html[data-reduced-motion="true"]` user-preference twin, plus **7 `@keyframes`**. It reports `carousels: 0` — there **is** a carousel, but it re-renders a single `<img>` from a JS index (autoplay interval `5s`, prev/next buttons), so no track exists in the DOM for the probe to see. Its two `scroll_effects` "pins" are just the fixed nav and an empty toast container, not effects. And its lone `entrance` reveal is the decode fade above, not a scroll animation.

## Production-safety note

- **Every technique here is production-safe** — this is a production-corpus exemplar with no spectacle. The costs are all elsewhere, in accessibility:
- **`tap-targets-risky` — the real defect.** 31 of 32 interactive elements sit below the 44px touch floor (the price buttons are `24px` tall; the carousel arrows are `24×24`). On a page whose entire conversion surface is those two price buttons, this is the thing to fix first. Pad the hit area with a pseudo-element rather than growing the visual box if you want to keep the type-scale-free look.
- **No `<h1>` anywhere** (headings start at `<h3>`). Screen-reader users get a document with no title node and a broken outline. Fixing it costs nothing visually — style the `h1` at `var(--text-base)` bold; a heading level is a semantic claim, not a size.
- **Bold is the *only* link affordance in prose** — no underline, no color shift from body ink. It scans cleanly because links are rare and body weight is `400`, but it fails any user who can't resolve weight (low vision, poor rendering). If you copy this pattern, add `text-underline-offset` on hover *and* keep the underline for users with `text-decoration` forced on. Do not ship weight-only links in a link-dense document.
- `focus-visible` is real and well done: `outline: 1px solid var(--colors-focus)` globally, with inputs and bordered controls swapping `border-color` to the same accent instead — the one place chroma is allowed.
- The **60s** progress-bar creep is safe but deceptive if the underlying operation can fail: pair it with a real error state, or a user waits 60 seconds watching a bar that will never complete.
- **Weight-only italics via `slnt -12`** synthesize a slant rather than using a drawn italic. For UI and short emphasis this is fine; for long-form italic passages a true italic cut is more legible.

## Extracted patterns
- prose-manifesto-landing — a landing page as a single centered column of argument, body-size bold headings, and plan rows inline in the paragraph flow; reuse when the product's value is an idea and a hero headline would flatten it.
- semantic-ramp-theming — one numbered neutral ramp aliased into semantic roles so a class on `<html>` re-points the whole palette; reuse for any multi-theme design system, especially with a blend-mode and variable-font axis carried as tokens.
- asymptotic-progress-bar — an indeterminate loading bar that leaps forward and then crawls toward a never-reached 100%; reuse for route changes and unknowable waits where a fake percentage would lie.
